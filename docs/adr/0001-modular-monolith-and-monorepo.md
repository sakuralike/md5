# ADR-0001：模块化单体与单仓结构

- 状态：已接受
- 日期：2026-08-01
- 对应需求：MVP-10、NFR 可维护性

## 背景

MVP 同时包含认证、档案指纹、候选密码、验证证据、信誉、管理审核和审计。团队规模不足以承担早期微服务的部署与一致性成本，但模块之间必须保持边界，便于后续拆分。

## 决策

1. 使用单仓管理 FastAPI、Vue 用户端、Vue 管理端和 .NET WPF。
2. API 采用模块化单体；模块只能通过公开服务接口协作，不跨模块直接依赖内部仓储。
3. 首版共享一个关系数据库，但表归属到明确模块；跨模块写入通过应用服务编排。
4. 长耗时任务通过 Worker 执行；API 不在请求内处理批量导入、通知或报表。
5. OpenAPI 是客户端契约事实来源，前端共享类型位于 `packages/api-contract`。

## 后果

- 优点：部署简单、事务清晰、便于端到端测试。
- 代价：需要代码评审持续约束模块边界。
- 拆分条件：某模块出现独立扩容、故障隔离、合规隔离或团队所有权需求时，再通过事件/接口拆分。
