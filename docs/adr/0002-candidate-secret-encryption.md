# ADR-0002：候选密码信封加密

- 状态：已接受，生产 KMS 提供商待定
- 日期：2026-08-01
- 对应需求：SEARCH-05、SUB-03、数据模型 9.2

## 背景

候选密码需要在授权揭示时恢复明文，因此不能使用单向账号密码哈希。同时，数据库泄露不应直接暴露候选密码。

## 决策

1. 候选密码使用应用层 AEAD 信封加密，保存密文、随机 nonce、算法和密钥版本。
2. 数据密钥由密钥管理适配器提供；生产密钥不进入数据库、镜像、日志或源码。
3. 去重使用独立密钥生成 HMAC 标签，不能用无密钥摘要替代。
4. 解密只允许在揭示服务的最小代码路径发生，并写入不含明文的审计事件。
5. 测试使用合成密钥和合成候选，生产密钥管理提供商在部署 ADR 中补充。

## 后果

- 密钥轮换需要支持多版本读取和新版本写入。
- 数据库备份和应用密钥必须分离保管。
- 本阶段只建立接口和安全边界；实际候选加密模块在 M2 实现并测试。
