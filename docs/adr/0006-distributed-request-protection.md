# ADR-0006：分布式限流与持久化幂等

- 状态：已接受
- 日期：2026-08-02
- 对应需求：AUTH-05、SUB-01～06、关键写操作可靠性

## 背景

API 会以多实例方式运行。只保存在进程内的计数器无法阻止请求绕过单实例限制，而只保存在 Redis 的幂等结果可能在缓存清理或故障后丢失，导致关键写操作重复执行。

## 决策

1. 集成和生产环境使用 Redis 固定时间窗限流器；计数键由命名空间、业务范围、客户端维度和时间桶组成。
2. Redis 不可用时限流保护失败关闭（fail closed），返回 `503 rate_limit.backend_unavailable`，避免无保护地继续处理敏感请求。
3. 本地单进程开发允许显式使用内存限流器；它不是生产后端。
4. 关键写操作的幂等记录持久化在业务数据库，而不是只放在 Redis。
5. 数据库只保存 `Idempotency-Key` 摘要、私有化所有者键、规范化请求摘要、状态、过期时间和可重放响应；不保存原始密钥或敏感请求体。
6. 同一所有者和作用域内，相同键与相同请求返回缓存结果；相同键用于不同请求返回 `409 request.idempotency_conflict`；仍在处理的请求返回 `409 request.idempotency_in_progress`。
7. 默认幂等记录保留 24 小时；后续由清理任务删除过期记录。

## 后果

- 多 API 实例共享限流状态，Redis 成为敏感入口的就绪依赖。
- 幂等结果可跨进程重启保留，但增加数据库写入和过期数据清理职责。
- 固定时间窗实现简单、可审计；如边界突发流量成为问题，可在保持接口不变的前提下升级为滑动窗或令牌桶。
