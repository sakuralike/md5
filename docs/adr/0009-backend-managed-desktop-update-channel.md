# ADR-0009：后端托管桌面更新通道与显式下载入口

- 状态：已接受
- 日期：2026-08-02
- 对应需求：DESK-09～13

## 背景

桌面端已经能够在服务端最低版本门禁失败时提示升级，但缺少统一的版本来源、发布生命周期和受控下载入口。若客户端直接依赖固定外部 URL、公开目录或任意第三方下载页，将难以撤回有问题的制品，也无法把版本、完整性、合法分发声明和管理员操作纳入同一审计边界。

桌面客户端仍是不可信环境。后端可以证明“某个发布记录经过受控流程并匹配指定字节”，但不能仅靠元数据替代用户的本地安全判断或构成外部法律意见。

## 决策

1. 后端以 `desktop_releases` 维护 `(channel, platform, architecture, version)` 唯一的发布记录，生命周期固定为 `draft → published → withdrawn`。
2. 创建、列出、上传、发布和撤回操作要求管理员 RBAC、当前会话 MFA、限流和审计；匿名客户端只拥有检查更新与下载已发布制品的能力。
3. 管理员创建草稿时先声明制品文件名、字节数和 SHA-256；上传接口以原始字节流写入临时文件，边读边校验大小与摘要，通过后才原子替换目标文件。
4. 发布操作重新计算持久化制品摘要与大小。生产环境不要求代码签名证书；发布记录必须确认允许分发并包含不少于 20 字符的合法性声明，审计仅保存该声明的 SHA-256 摘要。
5. 更新检查按通道、平台和架构严格隔离，只选择最高已发布版本；响应包含最低受支持版本、强制升级标记、发布说明、完整性元数据和后端生成的下载 URL。
6. 下载接口再次限定 `published` 状态，提供不可变缓存、ETag、标准 `Digest` 和 `nosniff`；撤回后立即拒绝新下载。开发环境使用受控本地目录，生产在发布前迁移到持久卷或对象存储/CDN。
7. 桌面端启动后自动检查稳定通道，但不静默下载、不执行安装包。用户必须显式点击，由系统浏览器打开后端下载入口；安装前可自行完成本地安全判断。
8. 管理端提供创建草稿并上传、失败后重试上传、复核、发布和撤回界面。浏览器校验版本格式、最低版本关系、摘要格式、合法分发确认、合法性声明以及重试文件名/大小；后端继续重新计算制品摘要并执行最终门禁。

## 后果

- 最低版本门禁和升级入口共享同一后端版本事实来源，管理员可以撤回有问题的版本并保留完整操作审计。
- 发布记录、文件大小和 SHA-256 能检测误传、截断和存储损坏；合法性声明提供可审计的分发依据，但不替代外部法律意见或用户的本地安全判断。
- 首版没有分批发布、差分包、静默安装、客户端内置下载器和自动回滚；这些能力需要独立威胁建模与 Windows 10/11 实机验收后再实施。
