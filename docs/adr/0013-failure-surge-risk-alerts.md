# ADR-0013：短时间窗失败激增风险告警与隐私边界

- 状态：已接受
- 日期：2026-08-02
- 决策范围：M4 社区信任与管理闭环

## 背景

`verification-v1` 已能把三个独立有效失败证据聚合为候选隔离，但仅有状态变化无法支撑安全运营人员确认、跟进和关闭异常。若直接把安装标识哈希、IP 网段或逐条关联证据复制到告警、API 和审计日志，又会扩大关联数据的暴露范围。

本轮需要先交付一个可验证的失败激增垂直切片，同时明确它不等同于完整的关联账号图谱或动态降权系统。

## 决策

1. 采用版本化规则 `risk-alert-v1`：候选在 15 分钟观察窗口内出现至少 3 个按“安装实例 → IP 网段 → 账号”优先级去重后的当前有效失败组，且聚合失败权重不低于 3.0 时，创建 `failure_surge/high` 告警。
2. 告警检测与反馈证据、自动候选状态变化处于同一数据库事务；任一步失败均不得留下部分状态。
3. 同一候选、告警类型和规则版本最多存在一个 `open` 或 `acknowledged` 活跃告警。已解决后出现新的材料变化和新一轮激增时，可创建新的告警。
4. `risk_alerts` 仅保存候选 ID、触发证据 ID、规则版本、观察窗口、独立失败数、聚合权重和当前处置投影，不保存 IP 网段、安装标识哈希或关联键。
5. `risk_alert_events` 采用不可变追加，记录系统检测及管理员状态转换。管理员处置状态为 `open → acknowledged/resolved`、`acknowledged → open/resolved`、`resolved → open`，禁止同状态空操作。
6. 管理端读取和处置必须使用当前 MFA 会话；状态转换必须提供 `Idempotency-Key` 和受控结果码。审计日志只记录对象 ID、聚合计数、前后状态和结果码，不复制管理员自由文本或关联标识。
7. 本 ADR 不声明关联账号识别、账号关系图、动态信誉权重或自动处罚已经完成；这些能力继续作为后续规则独立设计。

## 后果

- 三失败自动隔离现在具有可分派、可关闭、可重开且可审计的运营闭环。
- 风险页面能够解释触发窗口和聚合强度，同时避免把底层关联数据扩散到管理 API。
- 检测使用当前有效反馈而非累计历史事件，可避免已经改票的旧失败继续触发当前告警。
- 首版阈值与窗口仍为代码版本化常量；动态规则配置、通知网关和告警 SLA 留待后续切片。

## 未采用方案

- **直接把所有失败证据复制进告警**：增加敏感关联数据的副本和越权暴露面。
- **只依赖候选 `quarantined` 状态**：缺少告警负责人、处置结果和不可变运营时间线。
- **异步创建告警**：可能造成候选已隔离但告警丢失；当前规模优先保证同事务一致性。
