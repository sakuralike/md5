# ADR-0014：候选内关联证据图与动态限权

- 状态：已接受
- 日期：2026-08-03
- 决策范围：M4 社区信任与管理闭环

## 背景

M2/M3 已将反馈和桌面回执统一为候选有效证据，并以安装实例、IP 网段和账号维度做基础独立性判断。M4 第 5 次迭代又增加了失败激增告警，但若同一批关联账号在同一候选上重复提交，仍可能放大成功或失败权重。需要在不保存或扩散原始关联值的前提下，补齐候选内关联分析和动态降权。

## 决策

1. 采用版本化规则 `correlation-v1`。对单个候选的当前有效反馈建立无向图：非空 `installation_id_hash` 相同或非空 `ip_prefix` 相同即连边；使用并查集形成传递闭包关联组。空值不连边，图不跨候选。
2. 对每个关联组分别处理 `success` 和 `failure`：一个结果维度最多保留该组内最高单条有效反馈权重，其余同结果反馈标记为降权。独立组数和降权后的有效权重共同供 `verification-v2` 使用。
3. 每次材料变化成功写入后，在同一数据库事务内追加一条 `evidence_correlation_assessments`。快照绑定触发证据，保存规则版本、反馈/组/降权计数及原始和有效权重；通过触发证据唯一约束保证重试不重复。
4. 快照、管理 API、管理端页面和审计只暴露聚合计数、账号/反馈标识和信号类型；禁止返回原始 IP、安装哈希、关联键和候选秘密。
5. 本轮不自动封禁账号、不自动扣减信誉、不做跨候选身份图谱。任何处罚必须由后续独立规则、人工授权和不可变事件审计驱动。

## 后果

- 同一候选内的传递关联反馈不会在同一结果维度无限放大状态晋级或隔离判断。
- `verification-v2` 的状态判定仍保持可解释：每次变更都能追溯到触发反馈及聚合快照，但快照不复制敏感原始值。
- 关联分析当前为候选写入路径内同步计算，适合 MVP 规模；大规模跨候选分析、异步任务化、规则回放和误报率指标留待后续。
- 管理员能够调查“哪些账号/反馈通过哪类信号关联”，但不能从该接口直接取得原始 IP 或安装标识。

## 未采用方案

- **按单个账号直接去重**：无法识别账号之间的共享安装或网段，也会丢失独立反馈信息。
- **把所有关联反馈权重归零**：过度惩罚可能真实独立的结果；保留组内最高单条权重更符合最小降权原则。
- **保存完整关系图快照**：扩大敏感关联数据留存和越权风险；本轮只保存聚合结果。
- **立即执行自动封禁/扣信誉**：关联信号可能误报，且处罚需要独立的申诉、授权和回滚设计。
