# ADR-0017：提供商无关的 SMTP 邮件投递

- 状态：已接受
- 日期：2026-08-03
- 决策者：项目团队

## 背景

账号邮箱验证、密码重置和风险告警已经通过统一通知网关发送。此前实现的 `memory`、`log` 和签名 `webhook` 可以完成本地测试、占位投递与自有中继集成，但尚不能直接连接常见邮件服务商的 SMTP 发信入口。

本轮需要在不绑定特定云厂商 SDK 的前提下提供真实邮件传输，同时复用现有风险告警 Outbox、有限重试、失败终态、投递指标和人工重放能力。

## 决策

### 1. 新增统一网关后端 `smtp`

API 与 Worker 继续通过同一通知网关工厂选择实现。`smtp` 后端同时负责：

- 账号邮箱验证令牌；
- 密码重置令牌；
- 管理员风险告警及 SLA 超时提醒。

不新增邮件专用数据库表。风险告警继续在 `risk_alert_notifications.provider` 保存 `smtp`，并将本地生成的 RFC Message-ID 保存为 `provider_message_id`。

### 2. 传输安全模式

支持以下模式：

| 模式 | 典型端口 | 约束 |
|---|---:|---|
| `starttls` | 587 | 默认模式；先建立 SMTP 连接，再升级 TLS |
| `ssl` | 465 | 建连时直接使用 TLS |
| `none` | 自定义 | 仅允许 `local`、`test` 环境使用 |

TLS 使用系统信任链和默认主机名校验。非本地环境必须启用 `starttls` 或 `ssl`，并必须同时配置用户名和密码。用户名和密码只能成对出现。

### 3. 凭据与配置边界

SMTP 配置通过环境变量注入：

```text
NOTIFICATION_SMTP_HOST
NOTIFICATION_SMTP_PORT
NOTIFICATION_SMTP_SECURITY
NOTIFICATION_SMTP_USERNAME
NOTIFICATION_SMTP_PASSWORD
NOTIFICATION_SMTP_SENDER_EMAIL
NOTIFICATION_SMTP_SENDER_NAME
NOTIFICATION_SMTP_TIMEOUT_SECONDS
```

密码在配置对象中使用秘密类型保存，禁止进入日志、响应、文档、数据库或审计。仓库示例只能使用合成占位符；生产凭据应由部署平台的秘密管理能力注入和轮换。

### 4. 邮件内容与最小披露

首版只发送 UTF-8 纯文本邮件，不加载远程图片、不嵌入追踪像素、不发送附件。

- 账号邮件只包含一次性令牌、用途和安全提示。
- 风险告警邮件只包含告警 ID、通知类型、严重级别和处理时限。
- 风险告警邮件不得包含候选密码、证据原文、用户凭据、IP 网段、安装标识或关联键。
- 邮件接收地址仅在投递时从用户记录读取，不复制到投递运维表或管理 API。

### 5. SMTP 接受与最终送达的语义

SMTP 服务端接受邮件后，网关返回本地生成的 Message-ID。该结果仅表示当前 SMTP 会话接受了消息，不代表收件服务器最终送达、用户打开或点击。

最终送达、退信和投诉状态需要后续接入服务商回调或邮箱退信处理，不在本轮伪造为已送达。

### 6. 失败处理

- 风险告警 SMTP 异常继续由现有 Worker 转换为有限重试；第三次失败进入 `failed`，可在管理端幂等重放。
- 单个收件人被 SMTP 拒绝时视为投递失败，不记录服务端返回正文。
- 关闭 SMTP 会话失败不得覆盖已经产生的主要投递异常。
- 账号动作令牌继续沿用当前同步调用边界；将其改造为独立事务 Outbox 属于后续工作。

## 结果

### 正面影响

- 可连接支持标准 SMTP 的国内外邮件服务商，不绑定厂商 SDK。
- 复用已有通知提供商、回执、失败终态、指标和重放模型。
- STARTTLS、隐式 SSL、认证和秘密脱敏形成明确生产门禁。
- 纯文本模板降低 HTML 注入、远程资源泄露和模板供应链风险。

### 代价与限制

- SMTP Message-ID 不是最终送达回执。
- 暂无 HTML 品牌模板、多语言、退信自动处理和投诉抑制名单。
- 多 Worker 场景仍需要后续投递租约和更强的并发领取机制。
- 生产上线仍需在选定服务商环境完成 SPF、DKIM、DMARC、发件域名、频率和退信链路验收。

## 被否决的替代方案

- **直接绑定单一云厂商 SDK**：会过早锁定提供商，并增加账户令牌与风险告警两套适配逻辑。
- **生产允许明文 SMTP**：凭据和邮件内容可能被中间人读取，不满足安全基线。
- **首版发送复杂 HTML**：增加模板注入、远程资源和跨客户端渲染风险，当前告警价值不足以抵消复杂度。
- **把 SMTP 接受标记为最终送达**：语义不准确，会误导投递指标和运营判断。
