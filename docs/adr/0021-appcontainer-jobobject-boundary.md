# ADR-0021：AppContainer、Job Object 与显式 OS 隔离边界

- 状态：已接受
- 日期：2026-09-02
- 决策范围：Windows 插件进程与审核 Runner

## 背景

AppContainer、Job Object、目录 ACL、环境净化和句柄白名单共同构成插件进程层边界。仅依赖 AppContainer 的默认网络和注册表行为不可审计，也无法在策略变化后证明边界仍然存在。

## 决策

1. 每个插件使用由插件 ID 稳定派生的 AppContainer 配置文件和 SID；启动后必须断言 `TokenIsAppContainer`。
2. Job Object 强制施加内存、CPU、进程数、作业关闭即终止和未处理异常终止限制。
3. 安装目录只读、运行目录和获准私有目录按最小 ACL 授权；环境变量使用白名单和重定向目录；仅继承三条 stdio 管道句柄。
4. 管理员通过 `scripts/desktop-plugin-isolation.ps1` 为 SID 安装、验证和移除精确的 Windows 防火墙出站阻断规则与注册表拒绝写入 ACL。规则缺失或 SID 不匹配时，宿主和 Runner 拒绝启动插件。
5. 策略安装过程必须失败回滚；Probe 必须使用随机临时配置文件并自清理，不得修改全局默认规则。

## 结果

- OS 隔离从隐式默认行为提升为可读取、可审计、可清理的策略事实。
- 首次安装或换设备需要一次管理员策略安装；桌面端需要展示可操作的管理员提示。
- 防火墙策略和注册表 ACL 与本机现有安全策略冲突时，必须按 SID 精确作用域处理并保留回滚能力。

## 替代方案

- 仅依赖 AppContainer 默认拒绝：无法证明策略事实，拒绝。
- 创建全局出站阻断规则：会影响其他程序，违反最小作用域，拒绝。
- 仅在动态审核中探测：不能保护真实用户运行时，拒绝。

## 验证

- 管理员 Probe 已验证规则和 ACL 可创建、读取和清理。
- `synthetic.csharp` 正式启动路径已验证网络连接和注册表写入均被阻断。
- 规则缺失单测验证启动失败；桌面端完整测试和 PDPP conformance 通过。
