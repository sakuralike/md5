# ADR-0023：插件平台签章、OpenBao Transit 与撤销策略

- 状态：已接受
- 日期：2026-09-02
- 决策范围：插件发布、市场目录、下载、安装和撤销

## 背景

开发者签名只能证明包来自登记的开发者，不能证明平台已完成审核，也不能在密钥泄露或高风险发现后阻断旧版本。平台签章私钥必须与 API/Worker 运行进程隔离。

## 决策

1. 发布包必须同时具备开发者 Ed25519 签名和平台签章；签章载荷包含版本、制品摘要、Manifest 摘要、审核策略版本和发布通道。
2. 生产平台签章统一使用 OpenBao Transit Ed25519 密钥；API/Worker 只持有最小权限访问令牌，不读取或保存私钥。派生签章仅允许本地/测试环境。
3. 平台发布事实、撤销事实和公钥通过独立签名载荷公开；撤销版本或密钥进入撤销分区，目录、下载和桌面启动均阻断。
4. stable 与管理员受控 canary 使用同一签章和撤销链；canary 额外要求管理员身份、注册安装实例、设备签名和一次性短期票据。
5. 桌面端按缓存 TTL 验证撤销事实；高风险插件在无法刷新且超过离线窗口时停用，不得继续信任过期目录。

## 结果

- 发布、下载和启动的信任链可以独立复核并支持密钥轮换与紧急撤销。
- 需要保留签章载荷、公钥、撤销列表、ETag 和审计证据。
- OpenBao 运行可用性成为生产发布和发布后运维依赖，必须有失败关闭策略。

## 替代方案

- 只使用开发者签名：平台无法表达审核和撤销事实，拒绝。
- API 内置平台私钥：扩大泄露面，拒绝。
- 仅依赖在线目录、不签撤销事实：离线客户端可继续运行已撤销包，拒绝。

## 验证

- 当前服务端公开目录、下载票据、签章验证、撤销列表和桌面市场已有定向测试。
- OpenBao Transit 配置门禁和签章服务不可用失败关闭已有配置测试；生产轮换演练仍需目标环境证据。
