# ADR-0024：宿主自我降权与双进程边界

- 状态：已接受，P2 实施
- 日期：2026-09-02
- 决策范围：桌面宿主 UI、插件沙箱和受保护会话

## 背景

当前桌面宿主承担窗口、市场、会话和插件进程管理。即使插件进程被隔离，宿主本身仍持有用户级权限；宿主解析恶意插件响应或被本地攻击面利用时，插件沙箱不能保护整个用户环境。

## 决策

1. 目标架构拆分为 `Host.UI` 与 `Host.Sandbox`：前者负责窗口、市场和用户交互，后者以更低完整性负责插件进程、管道和 Broker。
2. 两者通过带 ACL 的命名管道通信；`Host.Sandbox` 只获得插件目录和短期 scope token，不获得可逆会话令牌、安装私钥或完整用户配置目录权限。
3. 宿主启动时校验自身二进制签名、Broker 方法白名单哈希和策略文件哈希；自检失败进入安全模式并停止第三方插件。
4. 双进程拆分前，现有 C# 宿主继续使用 AppContainer、Job Object、显式网络/注册表策略和协议双向限制；不得把 P2 目标架构误写成当前已部署能力。
5. `Pdpp.Sandbox.Core` 的 Rust 独立 IPC 内核在 P2/P3 迁移后成为桌面宿主与 Runner 的共同安全内核，C# 实现保留一个版本并行后移除。

## 结果

- 宿主被攻破时，受保护会话和平台签章材料仍与插件执行边界分离。
- IPC、完整性自检、短期 token 传递和故障恢复增加复杂度，必须以契约测试先行。
- P2 期间需要保持旧实现与新内核的可回退路径，不能一次性切换未验证的安全关键代码。

## 替代方案

- 保持单进程并依靠插件 AppContainer：不能降低宿主被攻破后的影响，拒绝作为最终目标。
- 让低权限进程持有可逆会话令牌：破坏最小披露边界，拒绝。
- 直接用 Rust/Tauri 重写整个桌面端：重写 UI 和既有安全资产，超出问题边界，拒绝。

## 验证

- P1 仅固化本 ADR 和当前边界；双进程完整性级别、命名管道 ACL、策略哈希和 Rust IPC 属于 P2/P3 验收。
