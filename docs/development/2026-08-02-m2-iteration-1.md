## 后端交付

### 档案域数据模型

- 新增 `archives`、`archive_fingerprints`、`password_candidates`、`submissions`、`points_ledger` 五张核心表。
- 指纹使用 `(algorithm, digest)` 唯一约束；候选使用 `(archive_id, secret_dedup_tag)` 唯一约束。
- 支持 MD5、SHA-1、SHA-256、SHA-512 完整指纹识别与严格十六进制校验。
- 新增 Alembic `20260802_0003`，已通过升级、降级到 base、再次升级门禁。

### 候选密码保护

- 新增 `CandidateSecretVault`，使用 AES-GCM、随机 nonce 和版本化派生密钥进行认证加密。
- 去重标签使用独立用途密钥的 HMAC-SHA-256；数据库不保存候选密码明文或无密钥密码摘要。
- 仅在揭示服务最小路径解密，响应设置 `Cache-Control: no-store`。
- 日志层新增递归敏感字段过滤器，覆盖密码、候选密码、令牌、Cookie、密文和 nonce 等字段。
- 当前本地/测试实现从应用主密钥派生版本密钥；生产 KMS/密钥管理适配器仍是发布前门禁。

### API 与业务规则

- `GET /api/v1/archives/search`：按完整指纹精确查询；匿名用户只得到匹配、状态统计和脱敏元数据，登录用户得到遮挡候选列表。
- `POST /api/v1/archives/submissions`：要求登录、授权声明与 `Idempotency-Key`；重复候选合并为新的提交证据，不重复创建候选。
- `POST /api/v1/archives/{id}/reveal`：只揭示最高可信的 `verified` 候选，执行每日配额并写入不含明文的审计事件。
- `GET /api/v1/me/submissions`：分页返回当前用户贡献及候选状态，不返回密码字段。
- 贡献创建待结算积分账本项，候选成为 `verified` 后的正式结算留待状态机迭代。

## Web 用户端交付

- 使用 `hash-wasm` 在浏览器分块计算 SHA-256 与 MD5，全程不上传文件内容。
- 展示文件名、大小、计算进度、耗时和结果；支持取消计算；建议文件上限可通过环境变量配置，默认 20 GiB。
- 支持手工输入完整指纹并自动识别算法、定位格式错误。
- 首页接入精确查询、匿名/登录可见性、候选遮挡、已验证候选揭示和复制后清理提示。
- 接入贡献表单，强制授权确认；提交完成后立即清空页面中的候选密码。
- 新增“我的贡献”页面，展示贡献时间、指纹摘要、来源和候选状态。
