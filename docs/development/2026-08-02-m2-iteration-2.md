### 版本化状态规则

`verification-v1` 当前规则：

- 至少 2 个独立成功证据，且失败权重低于 2.0：`pending/quarantined → verified`。
- 至少 3 个独立失败证据，或失败权重达到 3.0：`pending/verified → quarantined`。
- 关联键优先使用安装实例摘要，其次 IP 网段，最后账号；同一关联键同一结果方向只计最高权重。
- 普通账号权重 1.0，可信贡献者 1.25，审核员/管理员 1.5。
- 查询命中数和贡献次数不参与正确性证据计算。

### API 与幂等

- `POST /api/v1/candidates/{candidate_id}/feedback`：登录、限流、持久化幂等；支持 `success/failure` 创建或修改。
- 相同账号重复提交相同结果不会新增证据历史；修改结果会增加修订号并保留前值。
- `GET /api/v1/me/feedback`：分页返回当前用户的不可变反馈历史和候选当前状态。
- 档案查询候选摘要新增独立成功/失败数和当前账号有效反馈，不返回候选秘密。

### 积分结算

- 候选首次进入 `verified` 时，最早贡献的 `submission.pending` 流水转为 `posted`。
- 同一候选在首次验证前已有的后续重复贡献流水转为 `reversed`；首次验证后的新重复贡献立即记为 `reversed`，不再显示待结算积分。
- 首次验证时当前有效成功反馈各创建一条唯一 `verification.accepted` 已入账流水。
- 候选隔离后恢复为 `verified` 不重复结算首次贡献或相同反馈奖励。

## Web 用户端交付

- 查询结果展示每个候选的贡献数、独立成功数和独立失败数。
- 登录用户可提交“本地验证成功/失败”，当前选择以按压状态显示。
- 修改反馈后自动刷新查询；界面说明同一账号只保留一条有效反馈，历史仍追加保存。
- 候选达到失败阈值后进入 `quarantined`，从普通查询可见候选中移除，揭示接口同步拒绝。

## 自动化验证

新增 `apps/api/tests/test_m2_verification.py`，覆盖：

1. 两个独立成功反馈触发 `verified`。
2. 幂等重试和相同结果重提不重复证据、状态事件或积分。
3. 反馈修改只保留一个当前记录，并追加前后结果历史。
4. 三个独立失败反馈把已验证候选降为 `quarantined` 并暂停揭示。
5. 首位贡献积分入账、重复贡献积分冲正、有效验证者积分入账。
6. 同 IP 网段多个账号只计一个独立信号。
