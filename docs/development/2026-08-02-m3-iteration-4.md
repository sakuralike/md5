# M3 第 4 次开发迭代：管理端桌面发布工作台

- 日期：2026-08-02
- 分支：`codex/m3-desktop-verification`
- 目标：把上一轮后端桌面版本发布 API 接入 Admin，形成可恢复、可复核、受 MFA 保护的发布操作闭环。

## 本轮交付

### 1. 共享发布契约

- `packages/api-contract` 新增桌面发布通道、架构、生命周期、代码签名状态、创建请求、发布记录和列表响应类型。
- Admin 不再自行维护松散响应结构，发布页面与后端字段使用同一 TypeScript 契约。

### 2. 管理端发布服务

- 新增桌面发布服务，封装列表、创建草稿、原始制品上传、发布和撤回请求。
- API 客户端只对字符串 JSON 请求自动设置 `application/json`；制品上传显式使用 `application/octet-stream`，避免二进制请求被错误标记为 JSON。
- 创建前校验版本格式、最低版本关系、允许的制品扩展名、文件大小、SHA-256 格式以及 `verified` 签名元数据。
- 草稿上传重试要求本地文件名和大小与不可变发布记录一致；最终摘要仍由后端流式校验。

### 3. 桌面发布页面

- 管理导航和仪表盘新增“桌面发布”入口。
- 页面支持创建草稿并立即上传制品、查看全部发布记录、对失败草稿重试上传、显式确认发布及撤回。
- 发布列表展示通道、架构、最低支持版本、制品大小、SHA-256、签名记录、上传状态、下载次数和生命周期时间。
- 页面明确声明签名状态是发布流水线记录，不替代 Authenticode 实际验签；不在页面保存令牌、摘要以外的敏感发布材料或签名私钥。

## 自动化证据

- Admin 新增 4 个桌面发布服务测试，覆盖契约规范化、最低版本关系、摘要/扩展名/签名字段拒绝、重试文件一致性、大小格式和二进制上传请求。
- Admin 服务测试总数由 2 个增至 7 个，其中新增 1 个 API 内容类型边界测试，确认 JSON 与二进制请求不会混用 `Content-Type`。
- `./scripts/check.ps1 -SkipInstall` 已通过，覆盖后端静态检查/测试/迁移往返、全工作区 TypeScript 类型检查/测试/构建，以及 Windows Desktop Release 构建和 11 个测试。
- Docker Engine `29.6.2` 下 `docker compose config --quiet` 与 Admin 前端镜像 `docker build --check` 已通过。
- PR #15 CI 结果在本轮提交推送后补记。

## 仍需外部验收

1. 在 Windows 10/11 实机和真实签名测试制品上执行管理端发布到桌面下载的 E2E。
2. 正式发布机仍需独立完成 Authenticode 签名、证书链验证、时间戳和私钥保护。
3. 生产制品存储迁移到对象存储/CDN 后，复验大文件上传、反向代理限制、HTTPS 和缓存策略。
4. 管理端再次输入 TOTP、细粒度发布角色和双人复核属于后续高风险操作增强。
