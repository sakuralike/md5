# M4 第 4 次开发迭代：奖励补偿与信誉校正

- 日期：2026-08-02
- 分支：`codex/m4-reputation-compensation`
- 基线分支：`codex/m4-reputation-center`
- 目标：完成候选状态撤销/恢复后的积分补偿、信誉校正、人工首次验证结算和管理端可审计展示。

## 交付范围

### 后端与数据

- 新增 ADR-0012、Alembic `20260802_0010` 和不可变 `reward_adjustment_events`。
- 新增 `reward-compensation-v1`，按状态事件将首次贡献者和原始成功验证者的净奖励资格收敛到目标状态：
  - 进入 `verified`：恢复原始奖励资格；
  - 进入 `pending`、`quarantined` 或 `rejected`：将原始奖励资格校正为 0。
- 校正以状态事件、用户、奖励类型和来源引用建立唯一幂等边界，只追加积分、信誉和校正事件，不修改原始奖励。
- 自动状态转换和人工状态转换均在同一业务事务内执行校正；人工首次通过候选时同步结算原始贡献奖励。
- 信誉变化继续遵守 0～100 边界，校正事件保存实际变化量；重复状态请求和重复校正不会重复扣减或恢复。

### API 与管理端

- 候选详情新增不可变“积分 / 信誉调整”时间线。
- 人工状态转换响应新增本次积分、信誉和受影响账号汇总。
- 审计日志只记录聚合校正结果，不写入候选秘密、逐个账号明细或自由文本说明。
- 管理端状态转换成功提示展示校正汇总，并修复详情刷新覆盖成功消息的问题。
- 用户积分与信誉页面补充贡献/验证奖励失效和恢复的事件标签。

## 状态与奖励行为

| 状态变化 | 原始奖励处理 | 说明 |
|---|---|---|
| 首次进入 `verified` | 结算 | 首位贡献者和当时有效成功验证者获得原始积分/信誉奖励 |
| `verified → quarantined/rejected` | 失效 | 追加负积分和负信誉校正事件，原始奖励保持不变 |
| `quarantined/rejected/pending → verified` | 恢复 | 仅恢复已存在的原始奖励来源，不给后续证据追溯发奖 |
| 非 `verified →` 非 `verified` | 不变 | 若净奖励资格已为 0，不产生空校正事件 |
