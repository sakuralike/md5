# M4 第 5 次开发迭代：失败激增风险告警

- 日期：2026-08-02
- 分支：`codex/m4-risk-alerts`
- 基线分支：`codex/m4-reputation-compensation`
- 目标：把短时间窗独立失败激增从候选自动隔离扩展为可查询、可确认、可解决、可重开的管理端告警闭环。

## 交付范围

### 检测、数据和一致性

- 新增 ADR-0013、Alembic `20260802_0011`、`risk_alerts` 当前投影和 `risk_alert_events` 不可变事件表。
- 新增 `risk-alert-v1`：15 分钟内至少 3 个独立当前失败组且失败权重不低于 3.0 时创建 `failure_surge/high` 告警。
- 独立性继续复用验证聚合的“安装实例 → IP 网段 → 账号”优先级；告警只保存聚合数值和窗口，不保存关联键。
- 检测与反馈证据、自动隔离和奖励校正在同一事务执行；普通重复反馈或活跃告警期间的后续证据不会产生重复告警。
- 已解决告警不阻止后续新的材料变化形成新告警；本轮不实现完整账号关系图或动态信誉权重。

### API 与管理端

- 新增 MFA 管理 API：
  - `GET /api/v1/admin/risk-alerts`
  - `GET /api/v1/admin/risk-alerts/{alert_id}`
  - `POST /api/v1/admin/risk-alerts/{alert_id}/transition`
- 队列支持类型、严重度、状态、告警 ID 和候选 ID 过滤。
- 处置状态支持待响应、核查中、已解决和重新开启；结果码与目标状态强绑定，写操作具备持久化幂等、限流、请求号和最小披露审计。
- 管理端新增风险告警导航、仪表盘入口、队列、聚合证据详情、受控处置按钮和不可变时间线。
- 共享 TypeScript 契约和管理端服务测试同步完成。

## 隐私与安全边界

- 告警列表、详情、事件和审计均不返回 `installation_id_hash`、`ip_prefix` 或内部相关性键。
- 管理员处理说明只保存在告警处置记录，不复制到审计详情。
- 普通用户不能访问告警队列；管理员/审核员必须持有完成 TOTP 的当前 MFA 会话。
- 本轮告警是运营提示，不自动封禁账号、不直接扣减信誉，也不替代人工复核。
