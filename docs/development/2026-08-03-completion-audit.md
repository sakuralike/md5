### 3.1 Web 用户端

**已完成：**

- 用户注册、登录、浏览器刷新 Cookie、退出和登录会话查看/撤销。

## 5. P0/P1/P2 缺口与下一阶段

### P0：完成 MVP 管理与用户闭环后，才进入正式发布验收

1. **用户中心垂直切片**：密码重置/邮箱验证页面、个人资料/密码修改、用户 TOTP、授权声明记录、揭示历史、数据导出和账号删除申请。
2. **管理治理垂直切片**：真实仪表盘查询、审计查询/导出、用户状态和角色最小权限、封禁/解封、系统配置版本和高风险操作二次确认。
3. **案件与通知闭环**：账号申诉、案件与候选状态的显式编排、处理结果通知和可审计的重开/升级规则。

### P1：M5 验收基础

1. Playwright 核心旅程：注册/登录 → 本地指纹 → 查询 → 揭示/复制 → 贡献 → 桌面验证 → 反馈/案件；覆盖匿名、断网、取消、过期会话和重复请求。
2. Admin 页面级测试和安全测试：普通用户拒绝、对象级越权、CSRF/XSS、危险动作再认证、批量资源限制、最小披露。
3. Web Worker、20 GiB 边界/大文件性能、现代浏览器最近两个稳定版本和 Windows 10/11 实机验收。
4. 接入 SAST、DAST、依赖/镜像漏洞扫描、SBOM 与签名检查，设置高危阻断门槛。
5. 建立备份/恢复、Redis 丢失、Worker 重启、迁移回滚、密钥轮换演练，并记录 RPO/RTO。

### P2：生产发布与后续范围

1. 选择真实 SMTP 服务商并完成发件域名、SPF/DKIM/DMARC、配额、退信/投诉和最终送达验收。
2. 接入 Prometheus/OpenTelemetry/Grafana 或等价监控，建立队列、数据库、缓存、API、桌面崩溃和告警投递指标。
3. 完成 Authenticode、对象存储/CDN、预生产、RC、灰度、回滚和正式发布签字。
4. 跨候选图谱、自动处罚、批量贡献等不属于当前 MVP，应在 MVP 关闭后单独评审。

推荐下一轮只实现 P0 的“用户中心 + 管理治理”两个可验收切片，不继续扩展新的风险通知渠道；出口条件是：普通用户能完成账号安全和隐私请求，管理员能查看仪表盘/审计并执行受控用户处置，所有危险操作有二次验证和不可变审计。

## 6. 结论

当前仓库适合继续开发和内部演示，适合执行自动化回归，**不适合直接宣称 MVP 完成、对外开放或生产放量**。下一阶段的优先级不应再以“增加一个新后端模块”为主，而应收敛到：

1. 补齐用户中心和管理端缺口；
2. 用浏览器/桌面 E2E 把跨端主流程串起来；
3. 把安全扫描、恢复演练、监控和合规材料变成必过门禁；
4. 关闭堆叠 PR 合并链，确认 `main` 上的实际交付基线。
