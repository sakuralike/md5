# M4 第 7 次开发迭代：告警 SLA、值班指派与异步通知

- 日期：2026-08-03
- 分支：`codex/m4-alert-sla-notifications`
- 基线分支：`codex/m4-correlation-controls`
- 目标：把失败激增告警从“可查看、可处置”扩展为具备版本化时限、明确负责人和可审计通知投递的运维闭环。

## 交付范围

### SLA 与负责人

- 新增 ADR-0015 和 `risk-alert-sla-v1`，固定首版 15 分钟响应、240 分钟解决目标。
- 告警保存 SLA 规则版本、响应/解决截止时间和首次响应时间；管理 API 返回实时 SLA 状态，并支持负责人和超时筛选。
- 新增具备 MFA 的活跃 moderator/admin 操作者列表和显式指派 API；指派具备限流、持久化幂等、不可变事件和审计记录。
- 开始核查可在未指派时自动认领；解决保留负责人；重新开启清除负责人并生成新一轮 SLA 截止时间。

### 事务通知 Outbox 与 Worker

- 新增 `risk_alert_notifications`，检测、指派、响应超时、解决超时、解决和重开通知与业务变化同事务入队。
- `dedupe_key` 保证同一事件或 SLA 周期对同一接收人只入队一次。
- Celery Beat 每 60 秒扫描超时、每 15 秒投递；单条最多尝试 3 次并有限退避。
- 通知载荷采用最小披露，只发送告警 ID、严重级别、通知类型和适用截止时间；不复制密码、IP、安装标识或关联键。

### 管理端

- 风险队列新增负责人和超时筛选、SLA 徽标、响应/解决截止时间。
- 详情新增负责人指派、SLA 规则与状态、通知投递历史和负责人变化时间线。
- 共享 API 契约补齐 SLA、操作者、指派和通知类型；管理端服务测试覆盖筛选、操作者读取和幂等指派请求。
