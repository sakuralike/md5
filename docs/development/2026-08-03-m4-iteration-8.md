# M4 第 8 次开发迭代：通知投递运维与死信重放

- 日期：2026-08-03
- 分支：`codex/m4-notification-delivery-ops`
- 基线分支：`codex/m4-alert-sla-notifications`
- 目标：把风险告警通知 Outbox 从“有限重试”扩展为可接入生产提供商、可观测失败队列、可审计人工重放的运维闭环。

## 交付范围

### 通知提供商边界

- 新增 `webhook` 通知后端，与 `memory`、`log` 使用同一网关工厂；API 与 Worker 读取一致配置。
- Webhook 只允许 HTTPS，签名密钥至少 32 字符，超时限制为 1～30 秒。
- `notification-webhook-v1` 使用规范 JSON、UTC 时间戳和 HMAC-SHA256 签名；2xx 可返回提供商消息 ID。
- 账号动作令牌和接收地址只进入出站请求，不写入日志或投递表。

### 投递状态与死信治理

- Alembic `20260803_0014` 为风险通知增加提供商、回执、失败时间和重放审计元数据。
- Worker 每次尝试记录提供商；成功保存回执并清除失败信息，第三次失败进入死信终态。
- 新增 MFA 管理指标、分页过滤列表和人工重放 API；重放只接受失败记录，要求限流、`Idempotency-Key` 和原因。
- 重放复用原 Outbox 记录和 `dedupe_key`，状态重置为待发送，原失败摘要进入审计日志。

### 管理端

- 风险工作台新增待发送、已发送、失败/近 24 小时失败和最老待发送时长卡片。
- 新增失败通知队列，可按告警打开详情并手动重放。
- 告警通知历史展示提供商、回执、失败时间和重放次数，但不显示邮箱、Webhook 地址或签名材料。
- 共享 API 契约和管理端服务补齐指标、列表和重放类型。

## API 与配置

新增接口：

- `GET /api/v1/admin/risk-alerts/notification-deliveries/metrics`
- `GET /api/v1/admin/risk-alerts/notification-deliveries`
- `POST /api/v1/admin/risk-alerts/notification-deliveries/{notification_id}/replay`

新增配置：

- `NOTIFICATION_BACKEND=memory|log|webhook`
- `NOTIFICATION_WEBHOOK_URL`
- `NOTIFICATION_WEBHOOK_SECRET`
- `NOTIFICATION_WEBHOOK_TIMEOUT_SECONDS`
