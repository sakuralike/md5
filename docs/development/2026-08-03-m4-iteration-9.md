# M4 第 9 次迭代：SMTP 邮件投递通道

- 日期：2026-08-03
- 分支：`codex/m4-smtp-delivery`
- 基线：M4 第 8 次迭代通知投递运维闭环
- 目标：以标准 SMTP 为账号令牌和风险告警提供真实邮件传输能力，同时保持最小披露、有限重试和失败重放边界。

## 本轮范围

### SMTP 网关

- 统一通知工厂新增 `smtp` 后端。
- 支持 STARTTLS、隐式 SSL 和仅限本地测试的明文 SMTP。
- 支持可选 SMTP AUTH；非本地环境强制要求认证和加密。
- 使用系统默认 TLS 信任链与主机名校验。
- 发送 UTF-8 纯文本账户令牌和风险告警邮件。
- 为每封邮件生成 RFC Message-ID，并作为投递回执写入现有 `provider_message_id`。
- 单个收件人被拒绝时转换为提供商失败，风险告警继续进入现有重试/失败终态链路。

### 安全和隐私

- SMTP 密码使用秘密类型保存，不出现在配置对象文本表示中。
- 发件地址、发件人名称和服务器地址拒绝换行符，避免邮件头或连接参数注入。
- 风险告警邮件只包含告警 ID、类型、严重级别和处理时限。
- 不在投递表、管理 API、日志或审计中保存 SMTP 密码、收件地址或邮件正文。
- 生产环境禁止 `none`，并要求用户名和密码成对配置。

### 部署配置

新增环境变量：

```text
NOTIFICATION_SMTP_HOST
NOTIFICATION_SMTP_PORT
NOTIFICATION_SMTP_SECURITY
NOTIFICATION_SMTP_USERNAME
NOTIFICATION_SMTP_PASSWORD
NOTIFICATION_SMTP_SENDER_EMAIL
NOTIFICATION_SMTP_SENDER_NAME
NOTIFICATION_SMTP_TIMEOUT_SECONDS
```

`.env.example` 和 API/Worker Compose 服务均使用合成占位符，不包含真实服务商凭据。

## 自动化验收

`apps/api/tests/test_notification_smtp.py` 覆盖：

- STARTTLS 握手顺序、TLS 上下文、认证凭据和信封地址；
- 隐式 SSL 构造参数；
- 邮箱验证令牌纯文本模板；
- 风险告警最小披露模板与 UTC 截止时间；
- Message-ID 回执；
- 收件人拒绝转换为投递失败；

本轮不新增数据库迁移或 HTTP API；现有投递指标、失败队列和人工重放自动适用于 `provider=smtp`。
