- 日期：2026-08-03

- 对应计划：[下一阶段开发计划](../../项目文档/密码侦探社下一阶段开发计划-2026-08.md) N1

## 交付内容

### 再认证安全模型

- 新增 `POST /api/v1/me/security/reauthenticate`，使用当前密码确认用户身份；账号已启用 TOTP 时还必须提供有效动态码。
- 一次性凭据默认 5 分钟有效，绑定用户、当前会话族和精确操作目的：`password_change`、`totp_disable` 或 `account_deletion`。
- 原始凭据仅在签发响应中返回，数据库只保存 SHA-256 摘要；响应设置 `Cache-Control: no-store`，原始值不得进入日志、审计或幂等响应缓存。
- 签发接口不使用幂等键，同一用户、会话族和目的再次签发时撤销先前未消费凭据；签发频率单独限流。
- 消费使用行锁并与目标业务写入处于同一事务，确保过期、跨会话、跨目的和重复消费均被拒绝，业务失败回滚时不会提前损失凭据。

### 高风险操作接入

- 密码修改先消费 `password_change` 凭据，成功后保留当前会话、撤销其他会话并清理未消费再认证凭据。
- TOTP 停用先消费 `totp_disable` 凭据，成功后清除账号 TOTP 配置和活跃会话 MFA 标记。
- 账号删除申请先消费 `account_deletion` 凭据，再进入既有可撤销宽限期和异步去标识化流程。
- 三个消费接口继续使用 `Idempotency-Key`；相同幂等请求重放优先返回已缓存成功响应，不会再次消费凭据。

### 数据、契约与 Web

- 新增 `reauthentication_grants` 数据表和 Alembic `20260803_0016` 迁移。
- 同步共享 TypeScript API 契约、Web 服务层和认证 Store。
- Web 账号安全与隐私页改为先签发再认证凭据，再提交密码修改、TOTP 停用或删除申请；TOTP 动态码按操作目的隔离，避免复用错误表单状态。
