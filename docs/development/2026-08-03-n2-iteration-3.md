# N2 第 3 次开发迭代：用户治理只读总览

- 日期：2026-08-03
- 里程碑：N2 管理员治理中心
- 目标：在不提前开放危险写操作的前提下，完成管理员专属用户治理列表、详情和 Admin 工作台。
- 状态：本轮实现与本地统一门禁完成。

## 1. 范围与安全决策

本轮只实现用户治理的只读总览：

- 管理员可以按账号状态、角色、用户 ID、用户名或邮箱筛选用户。
- 管理员可以查看账号状态、角色、邮箱掩码、邮箱验证、TOTP、活跃会话、最近活跃和注册时间。
- 管理员可以查看用户积分余额、信誉事件、提交记录、举报/申诉案件、隐私导出队列和注销请求队列统计。
- 版主、普通用户和未完成 MFA 的账号由服务端拒绝。

本轮明确不实现封禁、解封和角色变更。原因是规格要求危险操作同时满足管理员近期再认证、TOTP、原因码、幂等和不可变审计；当前工程已有用户级再认证目的，但尚未建立管理员专用再认证凭据和对应写操作闭环。继续开放只读能力可以提前验证治理查询和最小披露，同时避免绕过安全门禁。

## 2. 后端交付

### API

新增：

- `GET /api/v1/admin/users`
- `GET /api/v1/admin/users/{user_id}`

实现位置：

- `apps/api/src/password_detective/modules/admin/users.py`
- `apps/api/src/password_detective/modules/admin/user_schemas.py`
- `apps/api/src/password_detective/modules/admin/router.py`

关键约束：

- 使用 `require_admin_mfa` 后再次限制 `UserRole.ADMIN`，因此 `moderator` 不可访问用户治理。
- 邮箱只在服务端筛选，响应使用首字符掩码；不会返回密码、令牌、TOTP 密钥、IP 或秘密材料。
- 列表按 `created_at DESC, id DESC` 稳定分页；活跃会话定义为未撤销且未过期。
- 会话聚合使用页面用户批量查询，避免用户列表出现逐用户 N+1 查询。
- 读取接口不写审计，避免查询审计递归；本轮无状态变更，因此不创建迁移。

## 5. 下一轮开发入口

5. 完成 Admin 危险操作确认对话框，随后再进入配置版本治理。
