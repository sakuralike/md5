## 1. 本轮目标与边界

本轮把用户治理从只读总览推进为首个受控写操作闭环，范围包括：

1. 管理员专用、短时、一次性、会话族绑定的用户治理再认证凭据。
2. 普通用户、可信贡献者和版主账号的停用与恢复。
3. 目标用户全部活跃会话撤销。
4. 当前密码、TOTP、结构化原因码、`Idempotency-Key`、乐观并发、对象级保护和不可变审计。
5. Admin 详情侧栏内的危险操作确认面板。

本轮继续不开放角色变更、管理员账号处置、服务账号处置和批量处置。这些能力需要更严格的双人复核、权限层级和配置版本治理，不能复用普通用户处置入口直接上线。

## 2. API 与安全链

| 方法 | 路径 | 作用 | 核心门禁 |
|---|---|---|---|
| `POST` | `/admin/auth/reauthenticate` | 签发用户治理一次性凭据 | 仅 `admin`、当前管理会话 MFA、当前密码、TOTP、限流、`Cache-Control: no-store` |
| `PATCH` | `/admin/users/{user_id}/status` | 停用或恢复账号 | 一次性再认证、原因码、幂等键、预期状态、对象级保护、审计；停用自动撤销活跃会话 |
| `POST` | `/admin/users/{user_id}/sessions/revoke` | 撤销全部活跃会话 | 一次性再认证、原因码、幂等键、预期活跃会话数、对象级保护、审计 |

安全语义：

- 再认证凭据绑定管理员用户、当前会话族和 `admin_user_governance` 目的，成功写操作后立即消费，过期或重放返回 `401`。
- 公开用户再认证接口只接受密码修改、TOTP 停用和账号删除三个目的，不能签发管理员治理凭据。
- 管理员不能处置自身；其他管理员和服务账号为受保护对象。
- 状态变更要求客户端提交 `expected_status`，会话撤销要求提交 `expected_active_session_count`；状态或计数变化返回 `409`，且不会消费再认证凭据。
- 同一幂等键和相同逻辑请求返回缓存响应；相同凭据换用新幂等键重放会被拒绝。
- 审计只记录动作、对象、前后状态、原因码、撤销数量、请求号和掩码网络前缀，不记录密码、TOTP、再认证令牌或自由文本。

## 3. Admin 工作台

`apps/admin/src/pages/UserGovernancePage.vue` 新增：

- 用户详情与治理一体侧栏。
- 停用账号、恢复账号和撤销活跃会话入口。
- 结构化原因选择、当前密码和 TOTP 确认表单。
- 操作成功/失败反馈及用户列表、详情自动刷新。
- 管理员自身、管理员角色和服务账号只读提示。

浏览器端不保存当前密码、TOTP 或再认证令牌；每次提交生成独立幂等键，操作完成或失败后清空认证字段。

## 4. 自动化验证

新增 API 测试 `apps/api/tests/test_n2_admin_user_actions.py`，覆盖：

- 管理员专属再认证和版主拒绝。
- 错误当前密码、TOTP 和 `no-store` 响应。
- 停用、恢复、自动会话撤销和审计最小披露。
- 幂等重放、再认证重放拒绝、状态并发冲突和自身对象保护。
- 会话计数并发冲突、凭据不被前置校验失败消费和会话撤销审计。

Admin 服务测试覆盖后端字段映射、`Idempotency-Key`、再认证、状态变更和会话撤销；页面 SSR 测试覆盖安全门禁文案。

专项门禁：API 用户治理 6 项通过；Admin 10 个测试文件、29 项测试通过，类型检查和生产构建通过。

## 6. 下一轮开发入口

N2 下一轮优先进入配置版本治理，而不是立即开放角色变更：

1. 建立系统配置版本、草稿、差异预览、发布和回滚数据模型。
2. 将阈值、限流、通知和桌面更新策略纳入可审计配置快照。
3. 对配置发布复用管理员再认证、原因码、幂等和乐观并发门禁。
4. 增加配置编辑/发布 Admin 工作台和迁移往返测试。
5. 在双人复核与权限层级方案冻结后，再实现受控角色变更和批量处置。
