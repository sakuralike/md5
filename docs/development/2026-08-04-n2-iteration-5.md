## 1. 本轮目标与边界

本轮将分散在环境配置中的首批运行参数纳入可审计的不可变版本治理，形成“草稿 → 差异确认 → 再认证发布 → 新版本回滚”的纵向闭环。

纳入首批快照的参数：

1. 每日明文查看配额。
2. 再认证凭据有效期。
3. 账号删除宽限期。
4. 桌面端最低受支持版本。
5. 桌面升级制品下载缓存时间。

本轮不提供自由键值编辑、定时生效、批量导入、秘密配置管理或角色变更。所有字段使用固定类型、范围和语义校验，避免把凭据、令牌或任意 JSON 纳入管理端。

## 2. 数据与 API

新增 `system_setting_versions` 不可变快照表和迁移 `20260803_0017_n2_setting_versions.py`。版本状态为 `draft`、`published`、`superseded`；回滚不会修改历史记录，而是创建引用目标版本的新发布版本。

| 方法 | 路径 | 作用 | 核心门禁 |
|---|---|---|---|
| `GET` | `/admin/settings/versions` | 分页查询版本历史和当前生效版本 | 仅管理员 + 当前会话 MFA |
| `GET` | `/admin/settings/versions/{version_id}` | 查询快照和基线差异 | 仅管理员 + 当前会话 MFA |
| `POST` | `/admin/settings/versions` | 创建不可变草稿 | 固定 Schema、原因码、基线版本、幂等、审计 |
| `POST` | `/admin/settings/versions/{version_id}/publish` | 发布草稿并更新运行时投影 | 配置治理一次性再认证、原因码、当前版本乐观并发、幂等、审计 |
| `POST` | `/admin/settings/versions/{version_id}/rollback` | 从历史版本创建新的发布版本 | 配置治理一次性再认证、预期当前版本、幂等、审计 |

管理员再认证接口新增 `admin_settings_governance` 目的。发布和回滚请求的幂等摘要不包含再认证令牌；服务端先执行版本冲突检查，再消费一次性授权，因此前置并发冲突不会浪费凭据。

## 3. 运行时投影

发布或回滚在同一事务内更新 `system_settings` 投影。以下现有业务路径已改为优先读取投影，并在尚未发布配置时回退到部署环境默认值：

- 归档候选明文查看的每日配额。
- 用户和管理员再认证凭据有效期。
- 账号删除申请宽限期。
- 桌面验证最低客户端版本。
- 桌面升级制品下载 `Cache-Control` 时长。

版本快照保存 SHA-256 摘要，审计只记录版本 ID、摘要、原因码和版本关系，不记录密码、TOTP、再认证令牌或秘密配置。

## 4. Admin 工作台

新增 `/settings` 系统配置治理工作台：

- 不可变版本列表、当前生效版本和版本状态。
- 固定字段草稿编辑器及范围约束。
- 相对基线的逐字段差异预览。
- 当前密码 + TOTP 的一次性再认证发布门禁。
- 从历史已发布版本创建新回滚版本。
- 发布、冲突和失败反馈；操作结束后清空认证字段。

共享契约新增配置快照、版本状态、原因码、差异和变更响应类型；Admin 服务统一映射后端字段并生成独立 `Idempotency-Key`。

## 6. 下一轮开发入口

1. 冻结角色层级、允许转换矩阵和受保护对象规则。
