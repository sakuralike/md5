## 1. 本轮目标

将已经完成的受控角色变更后端闭环接入 Admin 管理端，形成可操作、可分页、可复核、可验证且不会持久化敏感凭据的角色审批工作台，并清除当前文档中“Admin 审批工作台待实现”的过时描述。

## 2. Admin 工作台

- 新增 `/role-changes` 路由和“角色审批”导航入口。
- 新增角色变更服务层，统一请求列表、创建、批准和拒绝接口，`Idempotency-Key` 只放在请求头。
- 页面支持待复核/已批准/已拒绝/全部状态筛选、分页、加载态、空态、错误态、详情选择和手动刷新。
- 创建请求时校验目标用户 ID 和角色不可相同；创建成功后返回待复核队列第一页并保留成功反馈。
- 批准或拒绝时使用 `expected_status=pending` 执行乐观并发；批准成功后显示撤销的目标活跃会话数量。
- 切换选中项、筛选或分页时清理密码和 TOTP；创建、批准、拒绝无论成功或失败都会在 `finally` 中清理凭据。
- 密码、TOTP 和一次性再认证令牌只在页面内存与单次请求体中短时存在，不写入 LocalStorage、SessionStorage、URL、日志或错误详情。

## 3. 前端状态模型与测试

新增 `useRoleChanges` 组合式状态控制器，将加载竞态、分页边界、筛选、选中详情、再认证、创建和复核流程从页面渲染中分离。自动化覆盖：

1. 分页请求参数、范围显示、翻页后的选中项与凭据清理。
2. 创建请求、一次性再认证、幂等键生成和刷新后成功消息保留。
3. 批准请求、撤销会话数量反馈和已复核详情保留。
4. 拒绝请求及结构化复核原因。
5. 并发冲突等 API 错误的用户提示和失败后的凭据清理。
6. 无效目标、相同角色和非法 TOTP 在调用再认证前被拒绝。
7. 页面基础渲染、空态、分页按钮和双人复核提示。
8. 服务层路径编码、请求体、`expected_status` 和幂等请求头。

## 4. 安全边界

本轮没有放宽后端安全规则：

- 申请人与复核人必须不同。
- 仅允许 `user`、`trusted_contributor`、`moderator` 的固定转换。
- 管理员、服务账号、申请人自身和非正常账号继续受保护。
- 申请与复核均要求当前会话 MFA 和用户治理目的的一次性再认证。
- 批准前校验请求仍为 `pending` 且目标账号角色仍等于申请时角色。
- 批准成功后撤销目标账号活跃会话，并写入最小披露不可变审计。
- 独立角色事件时间线、紧急撤权、批量处置和管理员/服务账号角色治理继续关闭。
