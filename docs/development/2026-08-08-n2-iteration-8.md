# N2 第 8 次开发迭代：WP1 前端质量门禁与用户基础流程首批整改

- 迭代日期：2026-08-08
- 所属工作包：WP1 前端规范债务与工程门禁
- 执行状态：第一轮已完成，WP1 总体仍在进行中
- 分支：`codex/frontend-quality-gates`

## 1. 本轮目标

1. 建立根工作区、Web 和 Admin 统一 ESLint 门禁。
2. 将前端 lint 与业务 Vue 规范检查接入本地统一检查和 GitHub Actions。
3. 修复 `scripts/check.ps1` 在 Windows PowerShell 5.1 下无法解析空值条件访问的问题。
4. 完成用户端基础流程第一批迁移：应用外壳、首页和注册页优先使用 Shadcn-Vue 与 Tailwind。
5. 以“冻结历史欠账、禁止新增违规、逐批清零”的方式降低一次性全量迁移风险。

## 2. 工程门禁实现

### 2.1 ESLint

- 新增根级 `eslint.config.mjs`，统一启用 JavaScript、TypeScript 和 Vue 规则。
- Web 与 Admin 新增 `lint` 脚本，根 `pnpm lint` 串联两个应用的 ESLint 与前端规范策略检查。
- 明确禁止显式 `any`、未使用变量和非受控 `console`；Shadcn-Vue CLI 生成的 `src/components/ui/` 不参与业务组件规则误报。

### 2.2 前端规范策略

新增 `scripts/check-frontend-policy.mjs` 与 `scripts/frontend-policy-baseline.json`：

- 检查业务 `.vue` 文件中的 `<style>`、行内 `style`、十六进制颜色和原生表单控件。
- 对历史欠账建立精确到文件与规则的冻结基线；任何新增违规立即失败。
- 当历史违规减少但基线未同步收紧时也会失败，防止已整改欠账被重新放回基线。
- 本轮从 11 个文件、164 项历史违规降至 8 个文件、141 项，净减少 23 项；新增违规为 0。

### 2.3 统一入口与 CI

- `scripts/check.ps1` 在类型检查、测试和构建前执行 `pnpm lint`。
- 使用 `Get-Command` 显式取值，移除 PowerShell 7 专属的空值条件访问语法；运行时提示改用 ASCII，避免 Windows PowerShell 5.1 将无 BOM UTF-8 中文字符串按系统代码页读取后破坏语法。
- GitHub Actions 前端任务在安装依赖后执行 `pnpm lint`。
- `pnpm install --frozen-lockfile` 已通过，锁文件与工作区依赖声明一致。

## 3. 用户端基础流程首批整改

- 新增 `HomePage.test.ts` SSR 基础渲染测试，覆盖首屏本地指纹流程、查询空态与文件控件渲染。

### 3.4 基础组件
