# WP3 第 11 次开发迭代：Firefox 与 WebKit 跨引擎门禁

- 日期：2026-08-09
- 工作包：WP3 Web/Admin 端到端与视觉验收
- 范围：将完整 Web/Admin Playwright 旅程扩展到 Firefox 与 WebKit，建立浏览器隔离命令、CI 矩阵、跨浏览器统一门禁和真实 Safari 键盘验收边界。

## 交付

- `playwright.config.ts` 增加 `web/admin × chromium/firefox/webkit` 六个项目；每次浏览器命令单独启动 API、Web、Admin 并重建隔离 SQLite，避免三个引擎共享已消费令牌、角色审批和处置状态。
- 根 `package.json` 增加 `e2e:firefox`、`e2e:webkit`、`e2e:cross-browser`，默认 `e2e` 仍保持 Chromium，避免普通本地回归无意扩大为 90 项共享运行。
- `scripts/check.ps1` 增加 `-IncludeCrossBrowserE2E`，执行完整静态、单元、构建、迁移、桌面门禁后，依次运行 Chromium、Firefox、WebKit，各 30 项。
- GitHub Actions E2E 作业改为 Chromium、Firefox、WebKit 三项矩阵；每个矩阵单独安装浏览器、运行完整 30 项旅程，并使用浏览器名称隔离失败制品。
- 移动响应式测试取消 Firefox 不支持的 `isMobile` 上下文模拟，仅保留固定移动视口；真实触摸、iOS Safari 和 Android Chrome 继续作为设备验收项。
- Chromium 与 Firefox 保留首次 Tab 聚焦“跳到主要内容”及 Enter 激活门禁。无头 WebKit 无法注入 Safari 系统“完整键盘访问”偏好，因此 WebKit 预检直接聚焦跳过链接后使用 Enter 验证目标激活；真实 Safari Tab 可达性仍必须通过 macOS 人工矩阵验证。

## 状态边界

- 当前已证明 Playwright 捆绑 Chromium、Firefox、WebKit 在本地 Windows 环境和 GitHub Actions Linux 矩阵中均可完成相同 30 项业务、结构视觉和 Axe 旅程。
- Playwright WebKit 是 Safari 兼容预检，不是 macOS Safari 实机结论；直接聚焦跳过链接的 WebKit 分支不宣称真实 Safari 首次 Tab 行为已通过。
