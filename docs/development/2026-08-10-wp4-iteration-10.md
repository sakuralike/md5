# WP4 第 10 次开发迭代：候选秘密密钥轮换与回滚闭环

- 日期：2026-08-10
- 工作包：WP4 / M5 安全、恢复、性能与可观测性准入
- 本轮目标：关闭候选秘密旧密钥读取、当前密钥写入、稳定去重标签、批量轮换、回滚和自动化证据缺口。

## 1. 本轮交付

### 1.1 多版本密钥读取与单版本写入

`CandidateSecretVault` 现在维护“当前写入版本 + 历史读取版本”密钥集合：

- 新增候选秘密始终使用 `CANDIDATE_SECRET_KEY_VERSION` 对应的当前密钥写入；
- 已有候选根据记录中的 `secret_key_version` 选择历史密钥读取；
- 未配置版本、错误密文或认证标签失败统一返回安全错误，不回显密钥、密文或候选值；
- 密钥版本仅允许字母、数字、点、下划线和连字符，长度不超过 32；
- 密钥集合最多保留 8 个版本，非本地环境每个密钥至少 32 个字符。

为避免轮换改变唯一约束语义，`CANDIDATE_SECRET_DEDUP_KEY` 独立于加密密钥，并在正向轮换与回滚期间保持不变。未配置新变量时继续兼容原有 `APP_SECRET_KEY + v1` 数据。

### 1.2 轮换命令

新增 `scripts/rotate_candidate_secrets.py`：

- 默认只做 dry-run，只有显式 `--apply` 才提交；
- `--target-version` 必须与当前配置一致，避免操作员指向错误版本；
- 可用重复的 `--source-version` 限定来源版本；
- 报告只包含扫描、轮换、跳过数量和版本分布，不包含候选 ID、密文、去重标签或明文；
- 每条记录在改写前重新计算去重标签，若与库存标签不一致则整批停止并回滚。

轮换只更新 `secret_ciphertext`、`secret_nonce` 和 `secret_key_version`，不更新 `secret_dedup_tag`，因此不需要数据库结构迁移。

### 1.3 正向轮换与回滚演练

新增合成演练 `scripts/candidate-secret-rotation-drill.py`：

1. 在隔离 SQLite 数据库写入两条 v1 合成候选；
2. 使用 v2 当前密钥和 v1 历史密钥验证旧数据可读；
3. 执行 dry-run 并验证数据库完全未改变；
4. 执行 v1 到 v2 轮换，验证版本、明文可读性、密文变化和去重标签稳定；
5. 将 v1 重新设为当前版本，执行 v2 到 v1 回滚并再次验证；
6. 删除临时数据库，只保留不含秘密值的 JSON 报告与 SHA-256 清单。

`scripts/verify_candidate_secret_rotation_evidence.py` 独立校验八项结果、阶段计数、目标版本和 apply/dry-run 标记。

## 2. 自动化门禁

- API 单元测试覆盖旧密钥读取、未知版本拒绝、稳定去重标签、配置解析、dry-run、apply 和 rollback。
- `pnpm candidate-secrets:drill` 可执行演练与证据校验。
- `scripts/check.ps1 -SkipInstall -IncludeKeyRotation` 纳入本地统一门禁。
- GitHub Actions 新增 `candidate-secret-rotation` 作业，并上传 30 天提交级证据。

## 3. 运维与安全边界

- 运行步骤见 [候选秘密密钥轮换运行手册](../runbooks/wp4-candidate-secret-key-rotation.md)。
- `.env` 和 Compose 变量只是当前部署适配器；生产密钥仍必须由受控 Secret/KMS 注入，不得提交仓库或写入报告。
- 轮换前必须先部署能同时读取新旧版本且只写新版本的应用，再执行批量改写。
- 旧密钥只能在回滚窗口结束、库存旧版本计数为零、备份和回滚证据有效后移除。
- 本轮证明本地和 CI 的应用层轮换闭环，不等同于生产 KMS、HSM、跨区域备份或目标环境签字。
