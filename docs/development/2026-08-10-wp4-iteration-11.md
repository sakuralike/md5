# WP4 第 11 次开发迭代：多实例稳定性与单 Worker 故障收口

- 日期：2026-08-10
- 工作包：WP4 / M5 安全、恢复、性能与可观测性准入
- 本轮目标：建立可重复的 MySQL、Redis、API、Celery 多 Worker 混合稳定性门禁，并关闭共享 Worker 心跳和多 Beat 调度风险。

## 1. 本轮交付

### 1.1 多 Worker 心跳与可观测性

Worker 心跳由单一共享键改为按实例隔离的 TTL 键：

- 实例标识只以 SHA-256 截断摘要进入 Redis 键，不向指标暴露主机名；
- Worker 正常退出只清理自身心跳，不再误删其他实例的存活状态；
- API 汇总当前存活实例数并输出 `password_detective_worker_instances_ready`；
- `password_detective_dependency_up{dependency="worker"}` 在至少一个 Worker 存活时保持为 `1`；
- 读取端兼容旧共享心跳键，支持滚动部署期间的新旧版本并存。

### 1.2 单 Beat 与可横向扩展 Worker

Compose 将原先 `worker --beat` 拆分为两个职责：

- `worker` 只消费任务，可通过 `docker compose up --scale worker=N worker` 横向扩展；
- `scheduler` 单独运行 Celery Beat，避免多个 Worker 副本同时调度周期任务；
- MySQL SQLAlchemy 连接池新增 `pool_size`、`max_overflow`、`pool_timeout` 和 `pool_recycle` 配置，并保留 `pool_pre_ping`；
- SQLite 测试路径继续使用原有连接策略，不误传 QueuePool 专属参数。

### 1.3 隔离稳定性演练

新增 `scripts/multi-instance-stability-drill.ps1` 与 `scripts/multi_instance_stability_probe.py`：

1. 使用随机 Compose 项目名和独立端口启动 MySQL、Redis、API、单 Beat 与 3 个 Worker；
2. 并发执行 API readiness、MySQL 合成事务、Redis 临时键和 Celery noop 任务；
3. 主动停止一个 Worker，验证存活实例降为 2 且 Worker 依赖仍为可用；
4. 补回 Worker，验证实例数恢复为 3；
5. 等待队列清零和最终 readiness 通过；
6. 生成不含连接串、密码、令牌或业务数据的 JSON 报告。

`scripts/verify_multi_instance_stability_evidence.py` 独立校验最小 45 秒窗口、至少 3 个 Worker、单实例故障不中断、实例恢复、队列清零、四类探测各至少 10 次、零错误和宽松的回归延迟上限。

## 2. 自动化门禁

- API 单测覆盖实例心跳隔离、单实例清理后聚合可用和非 SQLite 连接池参数传递。
- `pnpm stability:multi-instance` 执行独立稳定性演练。
- `scripts/check.ps1 -SkipInstall -IncludeStability` 纳入本地统一门禁。
- GitHub Actions 新增 `multi-instance-stability` 作业，并上传 30 天提交级证据。

## 3. 统一门禁本地证据

60 秒隔离统一演练已通过：

- Worker：初始 3、主动下线后 2 且聚合可用、补回后 3；
- API 268 次、MySQL 272 次、Redis 279 次、Celery 270 次操作，合计 1089 次且错误数为 0；
- P95：API 23.229 ms、MySQL 23.494 ms、Redis 7.414 ms、Celery 12.145 ms；
- Worker 替补恢复 5.533 秒，最终队列深度 0，readiness HTTP 200。

以上数字是本机隔离回归证据，不是生产容量承诺。

## 4. 运维与验收边界

- 运行方式、参数、证据字段和故障处理见[多实例稳定性运行手册](../runbooks/wp4-multi-instance-stability.md)。
- 本轮验证的是单 MySQL、单 Redis 下的多 Worker 应用稳定性，不等同于 MySQL 主从/集群、Redis Sentinel/Cluster 或跨可用区高可用。
- CI 的 60 秒窗口用于防回归；生产放行仍需在 staging 执行数小时混合负载、容量趋势、连接数上限、慢查询、故障切换和资源水位验收。
- 生产 Secret/KMS、正式通知通道、跨区域恢复和目标环境签字仍独立关闭。
