# WP4 第 12 次开发迭代：Staging 长时稳定性准入合同

- 日期：2026-08-10
- 工作包：WP4 / M5 目标环境准入
- 本轮目标：把“数小时稳定性、容量预算、MySQL/Redis 高可用和 Go/No-Go”从文字待办转为机器可校验的执行合同，同时明确本轮不伪造目标环境完成证据。

## 1. 本轮交付

### 1.1 Staging readiness profile

新增 `infra/staging/readiness-profile.example.json`，明确：

- 稳定性窗口不少于 4 小时，资源样本不少于 240 个；
- API/MySQL/Redis/Celery 最低操作数、P95、错误率和连续错误阈值；
- API、Worker、Scheduler 拓扑和单 Beat 约束；
- MySQL 连接池容量预算；
- API、Worker、MySQL、Redis CPU 与内存上限；
- MySQL/Redis HA 模式、RTO/RPO、运行手册和证据文件；
- 四类必需审批角色和 Go/No-Go 模板。

### 1.2 容量预算与 Worker 并发

新增 `CELERY_WORKER_CONCURRENCY`，Compose 默认显式使用 2 个 Worker 进程，避免 Celery 按宿主机 CPU 数自动放大进程和数据库连接。

默认示例预算：

- 客户端进程：`2 × 2 + 3 × 2 + 1 = 11`；
- 单进程最大连接数：`5 + 5 = 10`；
- 计划最大连接数：110；
- 允许连接数：`floor((200 - 30) × 80%) = 136`；
- 剩余安全余量：26。

校验器会拒绝多 Scheduler、少于 2 个 API 副本、少于 3 个 Worker、少于 4 小时、HA 声明缺失、审批角色缺失、秘密字段或数据库连接超预算。

### 1.3 准入计划与审批模板

新增：

- `scripts/verify_staging_readiness_profile.py`：校验合同并生成脱敏计划；
- `scripts/staging-readiness-plan.ps1`：统一入口；
- `docs/runbooks/wp4-staging-readiness.md`：长时负载、资源趋势、MySQL/Redis 切换和故障处理；
- `docs/templates/wp4-staging-go-no-go.md`：证据清单、强制 NO-GO 条件和四角色审批。

生成计划的状态固定为：

```text
status=contract-valid
execution_status=not-run
go_no_go_status=pending-evidence
```

因此本轮只关闭“没有执行合同和审批标准”的缺口，不把计划校验冒充 staging 实测。
