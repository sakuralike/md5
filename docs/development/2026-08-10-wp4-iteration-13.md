# WP4 第 13 次开发迭代：资源趋势与 HA 执行证据合同

- 日期：2026-08-10
- 工作包：WP4 / M5 目标环境准入
- 本轮目标：把资源趋势、数据库连接预算和 MySQL/Redis 高可用切换结果固化为可机器校验的执行证据包，并严格区分合成合同夹具与目标环境实际执行证据。

## 1. 本轮交付

### 1.1 资源趋势证据 schema

新增 `infra/staging/resource-trend-report.example.json` 与 `scripts/verify_staging_execution_evidence.py`，覆盖：

- 4 小时窗口、时区明确的开始/结束时间、15 秒采样和不少于 95% 期望样本；
- API、MySQL、Redis、Celery 的操作量、P95、错误率和连续错误；
- API、Worker、MySQL、Redis 的 CPU/内存峰值与 P95；
- MySQL 连接峰值、预算上限、保留连接和剩余余量；
- Celery 队列峰值、最终清零和单 Worker 丢失约束；
- profile SHA-256 绑定与敏感键/值递归拒绝。

### 1.2 MySQL/Redis HA 切换证据 schema

新增：

- `infra/staging/mysql-ha-failover-report.example.json`；
- `infra/staging/redis-ha-failover-report.example.json`。

校验器要求：

- 只能使用 profile 声明的 HA 模式；
- 必须包含预检、切换触发、主节点变化、应用恢复、数据/队列完整性、幂等性和回滚就绪检查；
- MySQL 需证明读写恢复，Redis 需证明限流、Celery 恢复和队列清零；
- RTO/RPO 不得超过 profile，丢失记录数必须为 0；
- 证据必须与同一 profile SHA-256 绑定，且不得出现密码、令牌、Cookie、连接串或私钥。

### 1.3 证据包与本地/CI 入口

新增 `scripts/staging-evidence-contract.ps1` 和 `pnpm staging:evidence-contract`，复制合成示例、生成准入计划并验证以下 bundle：

```text
.local/staging-evidence-contract-wp4-iteration-13/
├── readiness-profile.json
├── staging-readiness-plan.json
├── resource-trend-report.json
├── mysql-ha-failover-report.json
├── redis-ha-failover-report.json
├── staging-execution-evidence-summary.json
└── checksums.sha256
```

合成夹具的结果固定为：

```text
status=contract-valid
evidence_kind=contract-fixture
execution_status=not-run
go_no_go_status=pending-evidence
```

`target-execution` 证据包只有在目标环境真实运行、证据完整且校验通过后，才能进入 `pending-approvals`；本轮没有把合成夹具或本地短时门禁冒充为 4 小时 staging/HA 验收。

## 4. 当前边界与下一轮入口

本轮关闭“资源趋势/HA 执行证据没有统一 schema 和校验器”的工程缺口，但尚未关闭：

- staging 实际不少于 4 小时的混合负载与资源趋势采集；
- 真实 MySQL/Redis HA 主节点切换、回切和目标环境 RTO/RPO；
- 目标环境的生产 Secret/KMS、通知、网络白名单和跨区域恢复；
- 技术、安全、运维、业务四角色实际签字与最终 Go/No-Go。

**下一轮开发入口：** 接入可控 staging 资源采集器和 HA 演练适配器，先完成 target-execution 证据包的脱敏、时钟、采样覆盖和回滚路径验证，再启动不少于 4 小时的人工触发长时门禁；任何没有真实目标环境时间线的报告仍保持 `not-run`。
