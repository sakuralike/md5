# WP4 第 15 次开发迭代：Prometheus 与 HA 平台导出接入

- 日期：2026-08-10
- 范围：WP4 M5 staging 真实平台证据导入
- 状态：平台导出适配合同实现完成；真实目标环境执行未开始

## 1. 本轮目标

在第 14 次迭代的通用资源/HA 源合同之前补齐实际平台导出层，使 Prometheus `query_range` 结果和托管 MySQL/Redis HA 事件能够先经过字段白名单、时间轴对齐、脱敏和来源类型校验，再进入既有 `target-execution` 证据物化链。目标环境不可用时只验证合同，不伪造 4 小时会话、HA 切换或审批。

## 2. 已实现内容

### 2.1 Prometheus 区间导出适配器

新增 `scripts/adapt_staging_platform_exports.py`，定义 `staging-prometheus-range-export-v1`。输入必须提供以下 10 个规范化序列：

- API、Worker、MySQL、Redis 的 CPU 百分比和内存 MiB；
- `database_connections`；
- `celery_queue_depth`。

每个序列必须保持 Prometheus HTTP API 的 `status/data/resultType/result/values` 结构，且只能包含一个已聚合时间序列。适配器要求所有序列使用完全一致的整秒 UTC 时间戳、严格递增、首尾覆盖声明窗口，并与 readiness profile 的 15 秒采样周期一致；连接数和队列深度必须为非负整数。

### 2.2 HA 平台事件适配器

新增 `staging-ha-platform-export-v1`，分别接收 MySQL 和 Redis 的平台事件。输入只允许：

- 依赖、HA 模式、执行窗口和统一执行组；
- 最后确认持久点、恢复点和丢失记录数；
- 事件类型、UTC 时间、检查状态，以及可选的原始平台事件 SHA-256。

原始平台事件 ID、端点、连接信息和任意未批准字段会被拒绝。适配器只保留原始事件的 SHA-256 摘要用于关联，不把平台内部标识或凭据写入证据源。

### 2.3 防伪与字段边界

- 三类平台导出必须共享 `execution_group_id` 和 `evidence_kind`。
- `target-execution` 继续拒绝名称包含 fixture、synthetic、test 或 mock 的采集器。
- 导出根字段、Prometheus 响应层级、HA durability 和事件字段全部使用白名单。
- 递归拒绝密码、令牌、Authorization、Cookie、API key、私钥及带凭据的 URL/查询值。
- 只接受 `synthetic_data_only=true` 的 staging 数据；脚本不接收、保存或打印目标环境认证信息。

### 2.4 人工执行与自动化

新增：

- `scripts/staging-platform-export-execution.ps1`：平台导出 → 通用源合同 → readiness plan → 聚合报告 → 最终证据包的一键人工入口。
- `scripts/staging-platform-export-contract.ps1`：生成 4 小时形状的 Prometheus/HA 合同夹具并走完整链路，但强制断言 `contract-fixture / not-run`。
- `pnpm staging:platform-export-contract`。
- `check.ps1 -IncludeStagingAdapters` 对第 14、15 次适配器及合同统一回归。
- GitHub Actions `staging-platform-export-contract` 独立作业，并归档 30 天合同制品。

## 3. 测试覆盖

新增 14 项测试，覆盖：

1. Prometheus/HA 合同导出完整适配并进入既有最终物化器；
2. 非夹具平台导出可形成 `target-execution` 源；
3. fixture 导出不能提升为 `target-execution`；
4. 缺失规范指标拒绝；
5. 跨序列时间戳错位拒绝；
6. 重复时间戳拒绝；
7. 非整数连接数拒绝；
8. Prometheus 标签中的敏感字段拒绝；
9. HA 原始平台事件 ID 拒绝；
10. 非法平台事件 SHA-256 拒绝；
11. 非整数采样周期拒绝；
12. 非整数丢失记录数拒绝；
13. 跨执行组导出拒绝；
14. HA 依赖类型不一致拒绝。

定向 Ruff、14 项新测试、`pnpm staging:platform-export-contract` 和 `./scripts/check.ps1 -SkipInstall -IncludeStagingAdapters` 统一门禁已通过。合同制品包含 961 个对齐采样点、四类各 10,000 次操作和完整 HA 生命周期，最终状态固定为 `contract-valid / contract-fixture / not-run / pending-evidence`。远端 CI `31429066132` 已触发，但所有独立作业在无 runner 分配、无执行步骤的情况下失败；该失败不是代码测试失败，需恢复 GitHub Actions runner 服务后重跑。

## 4. 目标环境执行方式

运维先从批准的监控/HA 平台导出脱敏 JSON，再执行：

```powershell
./scripts/staging-platform-export-execution.ps1 `
  -ResourceExport <prometheus-resource-export.json> `
  -MysqlExport <mysql-ha-platform-export.json> `
  -RedisExport <redis-ha-platform-export.json> `
  -OutputDirectory .local/staging-target-execution-wp4-iteration-15
```

平台特定 PromQL、端点和认证配置留在受控监控系统中，不写入仓库或证据包。导出文件通过适配和最终证据校验后，才允许把同一校验和提交给技术、安全、运维、业务四角色审批。
