- 日期：2026-08-10
- 范围：已部署 Staging 的 API、Web、Admin、认证链路和反向代理冒烟
- 状态：远端 Staging 冒烟通过；真实 4 小时会话、MySQL/Redis HA 切换和四角色审批仍未执行

## 1. 本轮目标

第 16 次迭代完成了证据包封存合同，但真实目标环境证据仍缺少一个可重复的基础运行入口。本轮把已部署 Staging 的最小可用检查固化为 `scripts/staging-smoke.ps1`，用于在不依赖域名和 HTTPS 的前提下验证服务可访问性、API 就绪状态、Web/Admin 页面、两端 `/api/` 代理和合成账号认证链路。

该入口是发布后 smoke，不会生成 `target-execution` 证据，也不会替代 4 小时资源趋势、MySQL/Redis HA 切换或四角色 Go/No-Go 审批。

## 2. 已实现内容

- 新增 `scripts/staging-smoke.ps1`，支持 `-BaseUrl`、`-WebUrl`、`-AdminUrl`、`-TimeoutSec` 和 `-SkipAuth`。
- 检查 API liveness/readiness，并要求数据库和 rate-limit 状态均为 `ok`。
- 检查 Web/Admin 页面 HTTP 200、页面标题和 `/api/v1/health/live` 反向代理。
- 默认使用唯一合成账号完成注册、登录和 `/me/profile` 校验；不输出访问令牌、密码或用户标识。
- 新增 `pnpm staging:smoke`，形成可重复的本地或远端 Staging 冒烟入口；通过 pnpm 传参时直接写参数，不额外添加 `--`。
