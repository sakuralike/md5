# WP4 第 18 次开发迭代：Staging 监控栈预检与长时观测入口

- 日期：2026-08-11
- 范围：Staging Prometheus、Grafana、Alertmanager、通知接收器部署与预检
- 状态：远端 Staging 监控预检通过；4 小时资源趋势和 MySQL/Redis HA 切换仍未执行

## 1. 本轮目标

第 17 次迭代已证明 Staging 应用和认证链路可以运行，但 4 小时目标执行仍缺少已部署、可重复验证且不会公开暴露的监控入口。本轮补齐 Staging 专用 Prometheus 标签、监控端口安全边界、静态合同门禁和远端运行 smoke，为后续长时采集提供基础设施。

本轮仍是观测预检，不生成 `target-execution`，不把短时监控运行时间提升为 4 小时稳定性、MySQL/Redis HA 或 Go/No-Go 结论。

## 2. 已实现内容

- 新增 `infra/staging/prometheus.staging.yml`，固定 API 采集目标为 `api:8000`，并使用 `environment=staging` 标签。
- 新增 `infra/staging/docker-compose.staging.monitoring.yml`，在 Staging Compose 组合中替换 Prometheus 配置。
- Prometheus、Grafana、Alertmanager 和通知接收器默认只绑定 `127.0.0.1`，避免监控管理端口直接暴露公网。
- 通知接收器镜像固定为 `python:3.12.13-alpine3.23`，不再使用浮动的 `python:3.12-alpine`。
- 新增 `scripts/staging-monitoring-smoke.ps1` 与 `pnpm staging:monitoring-smoke`，检查四个监控组件健康状态、Prometheus 活跃目标、`staging` 标签和 `up=1` 查询。
- `verify_monitoring_config.py` 升级到 `monitoring-config-v3`，把 Staging 配置、loopback 端口和固定镜像纳入校验和清单。
- 新增 3 项自动化测试，覆盖有效合同、Prometheus 公网绑定拒绝和 Staging 标签漂移拒绝。
