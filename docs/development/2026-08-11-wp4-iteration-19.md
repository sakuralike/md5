# WP4 第 19 次开发迭代：Staging 资源观测采集器与证据边界

- 日期：2026-08-11
- 范围：Docker 容器资源、MySQL 连接数、Celery 队列深度的目标主机观测
- 状态：采集合同、自动化测试和远端短时观测通过；长时业务探针与故障事件仍未执行

## 1. 本轮目标

第 18 次迭代已部署 Prometheus、Grafana、Alertmanager 和通知接收器，但当前目标主机使用 Docker 29 的 `overlayfs` 存储驱动，不应为了资源指标引入依赖容器层映射和 Docker socket 的公开 sidecar。本轮新增在目标主机按需执行的资源观测采集器，直接使用 Docker Engine stats，并组合 API 指标与 MySQL 连接数，先关闭“资源数据无法安全导出和机器复核”的缺口。

该产物固定为 `observation-only`，即使运行时间达到 4 小时，也不能在缺少业务操作窗口、单 Worker 丢失/恢复和 HA 时间线时升级为 `target-execution`。

## 2. 已实现内容

- 新增 `scripts/collect_staging_resource_observation.py`：
  - 自动发现运行中的 `api`、`worker`、`mysql`、`redis` Compose 服务；
  - 使用 `docker stats --no-stream` 采集并按服务聚合 CPU 与内存；
  - 从 MySQL 容器内部读取当前连接数，不输出数据库凭据；
  - 从 API Prometheus 文本读取 Celery 队列深度；
  - 输出不包含容器 ID、容器名、连接串、密码或令牌的 `staging-resource-observation-v1`。
- 新增 `scripts/verify_staging_resource_observation.py`：
  - 校验 UTC 时间线、采样间隔、四服务覆盖、非负资源值、连接数和队列深度；
  - 递归拒绝秘密字段、凭据形式值和容器身份字段；
  - 强制 `execution_status=observation-only` 与 `eligible_for_target_execution=false`；
  - 可生成校验报告和 SHA-256 清单。
- 新增 `scripts/staging-resource-observation.ps1` 与 `pnpm staging:resource-observation` 统一入口。
- 新增 `check.ps1 -IncludeStagingObservation` 门禁、合同示例和 5 项正负向测试。
- 本地统一门禁 ./scripts/check.ps1 -SkipInstall -IncludeMonitoring -IncludeStagingAdapters -IncludeStagingArchive -IncludeStagingObservation 于 2026-08-11 通过。

## 3. 远端 Staging 验证

在 `/opt/password-detective-staging` 使用服务器自带 Python 3.9 执行 30 秒、15 秒间隔的短时观测，得到 3 个样本并通过独立校验：

- API 峰值：CPU `0.12%`，内存 `81.81 MiB`；
- Worker 峰值：CPU `0.29%`，内存 `202.7 MiB`；
- MySQL 峰值：CPU `3.68%`，内存 `496.4 MiB`；
- Redis 峰值：CPU `0.55%`，内存 `10.53 MiB`；
- MySQL 连接峰值：`2`；
- Celery 队列峰值：`0`。

上述值仅证明采集链路在目标主机可运行，不是容量基线或性能结论。远端输出保存在服务器 `.local/staging-resource-observation-wp4-iteration-19/`，未纳入 Git，也不包含容器身份和秘密值。

## 4. 证据边界

本轮明确保留以下限制：

- 未生成 API、MySQL、Redis、Celery 的分窗口操作量、错误率和 P95；
- 未执行单 Worker 丢失和恢复；
- 未执行 MySQL/Redis HA 切换；
- 未证明不少于 4 小时和 95% 采样覆盖；
- 不能输入第 13 至 16 次迭代的 `target-execution` 封存与审批流程。

## 5. 下一轮入口

复用现有 `multi_instance_stability_probe.py` 的四类业务探针，开发 Staging 长时会话编排器：按固定窗口汇总操作量、错误率、最大连续错误和 P95，同时触发并记录一次单 Worker 丢失/恢复，再与本轮资源样本合并为 `staging-resource-samples-v1`。只有时间、采样覆盖、操作量和事件合同全部满足后，才允许进入 `target-execution` 校验。
