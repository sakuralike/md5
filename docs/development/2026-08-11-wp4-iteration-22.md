# WP4 第 22 次开发迭代：自动发布治理与桌面制品合法性

- 日期：2026-08-11
- 范围：WP4 发布治理、桌面更新制品完整性和合法分发声明
- 状态：实现完成，待统一门禁与 GitHub Git Data API 等效同步复核

## 决策

1. 项目 Staging 和发布不要求任何人员签字确认；发布结论由 `automated-evidence-gate` 生成。
2. Windows 桌面端不要求 Authenticode 或签名证书。
3. 桌面制品必须由服务端在上传与发布时重新计算文件大小和 SHA-256；发布记录还必须确认允许分发并提供合法性声明；历史发布记录缺少这些字段时不会再被检查或下载端点提供。
4. 合法性声明只作为可审计的项目内分发依据，不构成外部法律意见。
5. GitHub 远端同步只使用 Git Data API 创建等效提交并更新分支引用；不使用 HTTP/1.1 `git push`。
6. 产品内 N2 普通角色变更的双人审批属于权限治理功能，不是项目发布签字，本轮保持不变。

## 实现

### 桌面更新

- `desktop_releases` 增加 `distribution_authorized` 与 `legal_declaration`，迁移为 `20260811_0024_desktop_release_legality.py`。
- 创建草稿要求确认允许分发且合法性声明至少 20 字符；发布前再次检查这两个字段。
- 上传和发布均以服务端计算的文件大小及 SHA-256 为完整性事实来源；任一不匹配均拒绝。
- 发布审计记录制品 SHA-256、分发确认和合法性声明的 SHA-256，避免将完整声明重复暴露在审计详情中。
- Admin、共享 TypeScript 契约和 Windows 桌面更新提示改为完整性/分发确认语义，不再显示签名证书字段。

### Staging 自动决策

- readiness profile 改为 `release_decision.mode=automated-evidence-gate`。
- 目标执行证据校验通过后输出 `go`；封存归档以 `ready-for-release` 作为交接状态。
- 新模板 `docs/templates/wp4-staging-release-decision.md` 记录候选提交、候选树、脱敏证据、checksum、阈值、风险和自动结论，不含人员签名栏。
- 合成 `contract-fixture` 继续保持 `not-run/pending-evidence`，不能被误作目标环境通过证据。

## 验收边界

- 自动 `GO` 仍依赖真实 `target-execution` 的不少于 4 小时稳定性、资源趋势、MySQL/Redis HA 切换、校验和、风险阈值和回滚验证；本地合同测试不替代这些目标环境事实。
- 服务端 SHA-256/大小校验能保证提交制品的完整性和可追溯性，但不能替代用户的本地安全判断或外部法律意见。
- 发布治理去签字不改变业务权限审批：N2 角色变更仍要求独立双人复核。

## 验证计划

1. 运行 API 桌面发布专项、Staging profile/执行证据/封存专项测试。
2. 运行 Admin 服务测试、TypeScript/lint、Windows 桌面客户端测试和迁移检查。
3. 运行 `./scripts/check.ps1 -SkipInstall -IncludeMonitoring -IncludeStagingReadiness -IncludeStagingEvidence -IncludeStagingAdapters -IncludeStagingArchive -IncludeStagingObservation -IncludeStagingSession`。
4. 提交后通过 GitHub Git Data API 生成等效远端提交，比较远端与本地树 SHA-1 一致性。
