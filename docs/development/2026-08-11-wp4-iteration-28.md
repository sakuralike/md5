# WP4 第 28 次迭代：无外部 KMS 的生产文件型秘密管理

- 日期：2026-08-11
- 范围：生产秘密注入、容器最小权限、加密备份、恢复和候选密钥轮换
- 决策：外部 KMS 非当前上线前置条件

## 目标

将既有 AES-GCM 候选秘密密钥环从普通环境变量升级为可生产使用的文件型 Docker Secrets，并补齐独立秘密生成、宿主机权限检查、认证加密备份、恢复和版本轮换能力，同时保持本地开发 `.env` 兼容。

## 代码和配置

1. `apps/api/src/password_detective/core/config.py`
   - 支持 8 类 `*_FILE` 配置；
   - 文件引用优先用于生产 Secret 注入；
   - 直接值和文件引用同时为非空时拒绝启动；
   - 文件必须可读、UTF-8、无 NUL，最大 64 KiB；
   - 错误信息不回显宿主机秘密路径。
2. `docker-compose.production-secrets.yml`
   - API、Worker、Scheduler 只接收秘密文件路径；
   - MySQL 使用 `MYSQL_PASSWORD_FILE`；
   - Redis 从 Secret 生成权限受限的临时配置；
   - 秘密运行时复制目录使用 tmpfs。
3. `infra/docker/api-entrypoint.sh` 与 `infra/docker/api.Dockerfile`
   - 入口进程以 root 读取宿主机 root-only Secret；
   - 复制后归属 `app` 用户并设置 `0400`；
   - 通过 `su-exec` 降权执行 API、Worker 或 Scheduler 命令。
4. `scripts/manage_production_secrets.py`
   - `init`：生成独立随机秘密并拒绝覆盖；
   - `verify`：检查权限、长度、密钥环和连接地址一致性；
   - `backup`：Scrypt 派生 + Fernet 认证加密；
   - `restore`：错误口令或篡改时拒绝；
   - `rotate-candidate`：先加密备份，再新增候选密钥版本并保留旧版本。

## 安全边界

- 工具和合同测试只使用合成秘密。
- 真实秘密目录必须位于仓库外并由 root 控制。
- 备份口令与 `.pdsb` 备份分离保存。
- 本方案不能抵御宿主机 root 已被攻陷的场景；此时按全部生产秘密泄露执行应急轮换。
- 常规候选加密密钥轮换不得同步更改稳定去重密钥。
