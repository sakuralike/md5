# WP4 第 30 次开发迭代：管理端 SMTP 邮件投递工作台

- 日期：2026-08-11
- 范围：参考邮件配置页面，补齐管理端邮件投递状态展示与安全测试入口。
- 目标：让管理员在 MFA 保护的系统配置页确认部署注入的 SMTP 配置，并向合成收件地址发送一次测试邮件；不把邮件凭据变成浏览器可写配置。

## 本轮实现

### API

- 新增 `GET /api/v1/admin/settings/email-delivery`：返回通知后端、SMTP 主机/端口/安全模式、发件人、主题前缀、纯文本页脚、认证状态和配置来源。
- 新增 `POST /api/v1/admin/settings/email-delivery/test`：仅 `admin` 且完成 MFA 的会话可调用，按管理员入口限流，收件地址使用服务端邮箱格式校验。
- 测试邮件固定为 UTF-8 纯文本，主题带有系统前缀和“邮件投递测试”标识，正文不包含密钥或用户敏感数据。
- 成功和失败均写入最小披露管理审计；失败不保存 SMTP 服务端原始响应，成功只保存提供商类型、安全模式和 Message-ID。

### Admin 前端

- 系统设置页新增“SMTP 邮件投递”工作台，按参考图展示发件人、主题前缀、页脚、服务器、端口、加密方式、用户名和凭据状态。
- 所有 SMTP 配置均为部署环境只读状态；SMTP 密码永不回传、回显或由前端编辑。
- 新增测试收件地址和“发送测试邮件”操作，展示“SMTP 接受不等同最终送达”的提示。
- 组件继续使用 Shadcn-Vue 与 Tailwind 工具类，没有新增自定义 CSS。

## 未改变的安全边界

- SMTP 密码继续由部署环境或 Docker Secrets 注入，不进入 API 响应、数据库、日志、审计或文档。
- Message-ID 仅表示 SMTP 会话接受，不表示最终送达、打开或点击。
- 本轮不新增 HTML 模板、远程图片、追踪像素或附件能力。
