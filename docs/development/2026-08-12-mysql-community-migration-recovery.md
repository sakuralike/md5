# 2026-08-12 MySQL 社区群组迁移恢复修复

## 问题

目标服务器在执行 Alembic `20260812_0032` 时，MySQL 已完成建表、加列、索引、外键和板块回填，但最后将 `community_posts.board_id` 改为非空时，因为 `alter_column` 未声明 `existing_type` 而失败。MySQL DDL 非事务化，数据库因此停留在“结构基本完成、Alembic 仍记录 0031”的部分迁移状态。

## 修复

- `board_id` 非空变更显式声明 `existing_type=String(36)`。
- 0032 增加 MySQL 重入检测：仅当四张群组表、`board_id` 和 `group_id` 均已存在时进入恢复路径。
- 恢复路径只重新执行幂等板块回填、检查是否仍有未映射主题，再完成非空约束；不会重复建表、索引或外键。
- 若存在无法映射的主题，迁移立即失败，禁止以错误默认值掩盖数据问题。
- 新增部分 DDL 成功后的恢复测试和未映射数据阻断测试。

## 目标环境证据

修复前服务器实测：Alembic 为 `20260812_0031`，群组四表和主题两列已经存在，`board_id` 无空值但仍允许 NULL。该状态正是本次恢复路径覆盖的边界。
