# 2026-08-14 Admin TOTP 默认关闭调整

## 目标

取消管理员首次登录必须绑定 TOTP 的门禁，使普通用户、审核员和管理员均以“默认关闭、主动启用”为统一策略。

## 行为契约

1. 新建账号没有 `totp_enabled_at`，因此 TOTP 默认关闭；本轮不新增数据库迁移。
2. 未启用 TOTP 的 `moderator`/`admin` 可使用用户名或邮箱与密码登录 Admin，并访问角色允许的管理 API。
3. 账号主动启用 TOTP 后，登录必须提交有效动态码；旧的未验证访问令牌不能访问管理 API。
4. 高风险操作始终要求当前密码签发一次性再认证凭据；账号已启用 TOTP 时，再认证额外要求动态码。
5. 本轮不批量停用既有 TOTP，不清除既有密钥；已启用账号继续按增强策略保护。

## 实现范围

- API：管理员准入依赖由“必须已绑定并验证”改为“已启用时必须验证”。
- Admin：删除 `enrollmentOnly` 会话状态、强制 `/totp-setup` 跳转和首次绑定文案。
- 路由：`/totp-setup` 改为登录后可选安全增强页面。
- 测试：覆盖默认关闭准入、密码再认证、主动启用后动态码门禁和页面文案。

## 安全说明

默认关闭降低了特权账号的初始认证强度。现有补偿控制包括特权角色限制、登录限流、HttpOnly 刷新 Cookie、短期访问令牌、不可变审计，以及高风险操作的当前密码和一次性再认证凭据。生产运营仍应鼓励高权限人员主动启用 TOTP。
