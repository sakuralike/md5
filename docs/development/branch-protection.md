# 主分支 CI 与分支保护验收清单

- 更新日期：2026-08-02
- 适用分支：`main`
- 当前状态：配置文件已完成，因仓库尚无托管远端而未执行

## 托管 CI 必须通过的任务

以下名称来自 `.github/workflows/ci.yml`：

- `api`
- `frontend`
- `desktop`
- `container-images`

其中 `api` 必须使用真实 Redis 服务执行集成测试，并完成 Alembic 升级、降级和再次升级；`container-images` 依赖 API 与前端任务成功。

## 建议分支保护

1. 禁止直接推送到 `main`，仅允许通过 Pull Request 合并。
2. 至少 1 名非提交者批准；安全或数据模型改动建议 2 名批准。
3. 要求上面 4 个状态检查全部成功且分支为最新。
4. 要求所有评审意见已解决；新提交使旧批准失效。
5. 禁止强制推送和删除 `main`。
6. 管理员同样遵守规则；紧急绕过必须记录原因并补做复盘。
7. 若平台支持，启用秘密扫描、依赖告警和合并前代码扫描。

## 验收步骤

1. 创建托管远端并推送 `main`。
2. 确认首次 CI 全部成功，并保存运行链接或截图到迭代记录。
3. 配置上述保护规则。
4. 创建一个测试分支和 Pull Request，确认失败检查会阻止合并。
5. 检查通过并获批后合并，确认 `main` 再次通过 CI。
6. 在 `docs/development/phase-status.md` 将托管 CI 门禁改为完成，并记录日期与证据。
