# 跨平台视觉基线策略

- 更新日期：2026-08-09
- 适用范围：Web、Admin 的 Playwright 视觉验收
- 当前状态：策略已冻结；本地 Chromium、Firefox、WebKit 结构化视觉门禁已执行，远端矩阵状态待本轮 CI 回填，跨操作系统像素基线尚未批准

## 1. 目标与边界

视觉验收用于发现页面级溢出、关键区域越界、内容遮挡、响应式断裂和非预期样式回退。当前自动化以结构化布局断言、全页 PNG 报告附件和 Axe 严重/关键违规扫描为主，不把不同操作系统生成的像素截图直接互认。

以下证据可以作为当前 CI 的自动化依据：

- 固定视口下的关键区域边界与页面级横向溢出断言。
- Playwright HTML 报告中的全页 PNG 附件。
- 同一执行环境内生成并复核的像素差异结果。
- Axe WCAG 2 A/AA 与 2.1 A/AA 严重、关键违规结果。

以下内容不能仅凭当前自动化标记为完成：

- 跨 Windows、Linux、macOS 共用同一份像素基线。
- 字体栅格化、滚动条、系统控件和浏览器版本差异的自动批准。
- 设计一致性、信息层级、文案易懂性和真实辅助技术体验。

## 2. 基线分层

| 层级 | 内容 | 当前门禁 | 批准方式 |
|---|---|---|---|
| L1 结构基线 | 视口、页面宽度、关键容器边界、无横向溢出、关键控件可见 | PR/推送必须通过 | 自动化断言 |
| L2 报告截图 | 全页 PNG，用于失败定位和人工复核 | 当前 Chromium 生成 | 评审者人工确认 |
| L3 像素基线 | 同 OS、同浏览器、同字体和同 DPR 的差异比较 | 尚未纳入统一门禁 | 每个运行通道单独批准 |
| L4 体验验收 | 设计、文案、读屏器、缩放、高对比度和真实设备 | 尚未完成 | 产品、设计、QA 或无障碍评审签字 |

## 3. 运行通道与目录约定

像素基线必须按以下维度隔离，禁止跨通道复制后直接批准：

```text
<app>/<browser>/<os>/<viewport>/<route-or-journey>.png
```

建议通道标识：

- `chromium-linux-ci`：GitHub Actions `ubuntu-latest`，作为持续集成参考通道。
- `chromium-windows-local`：Windows 本地开发机，仅用于本机回归，不替代 CI。
- `edge-windows-target`：目标 Windows 环境的 Microsoft Edge。
- `firefox-linux-ci`：后续增加的 Firefox 自动化通道。
- `webkit-macos-target`：macOS/Safari 接近通道；正式 Safari 仍需实机人工验收。

每个通道必须固定浏览器版本、字体包、设备像素比、区域设置、时区、视口和动画策略。升级任何一项都应生成新的基线评审，而不是批量无条件覆盖。

## 4. 稳定化规则

- 仅使用合成账号、合成 ID、固定状态和隔离数据库。
- 动态时间、随机标识、一次性凭证和敏感内容不得进入基线；必要时遮罩或使用稳定替身。
- 截图前等待页面明确的加载完成条件，不使用任意长时间休眠。
- 禁用动画或等待动画结束；保证字体加载完成。
- 失败时保留截图、页面 URL、视口、浏览器版本、差异摘要和 Playwright Trace；认证材料场景继续关闭或脱敏敏感制品。
- 不使用无界重试掩盖波动；出现波动时登记根因、受影响通道和修复提交。

## 5. 差异批准流程

1. 自动化先通过 L1 结构断言和 Axe 门禁。
2. 评审者查看预期截图、实际截图和差异图，确认差异来自明确需求或组件升级。
3. 批准记录至少包含页面、通道、变更原因、评审人、日期和提交摘要。
4. 仅更新发生预期变化的基线；禁止一次性接受全部未知差异。
5. 基线超过 90 天未执行、浏览器跨大版本升级或字体镜像变化时，标记为待重新批准。
6. 生产放行前，至少完成目标 Edge/Windows 和目标 Safari/macOS 的人工视觉复核；未执行的通道保持“未验证”。

## 6. 当前证据与下一步

截至 2026-08-09，Web/Admin 相同的 30 项旅程已分别在本地 Playwright Chromium、Firefox、WebKit 通过，覆盖公开入口、认证核心旅程以及主要已登录业务页面的桌面/移动结构化视觉、无溢出和 Axe 严重/关键门禁；GitHub Actions 已配置为在 `ubuntu-latest` 上并行运行三引擎矩阵。该结果不证明 Edge、真实 Safari、Windows/macOS 像素一致、真实辅助技术或目标环境已验收。

下一步：为 Linux CI 三引擎分别建立受控结构/像素基线试点，再增加 Edge/Windows 和真实 Safari/macOS 通道；所有跨平台差异仍按通道独立批准，Playwright WebKit 不继承真实 Safari 的批准结论。
