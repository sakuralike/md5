# MD5后端API

> 状态：历史需求参考，不作为当前开发基线。若与 v3.0 规格冲突，以当前规格说明书为准。

> 原始来源：`MD5后端API.docx`

一、API接口总览

根据文档，系统主要包含以下几类API接口，其中部分接口需要为桌面端进行适配。

1. 公共接口

用户认证接口：用于用户的注册与登录，获取操作权限。

查询接口：提供正向（哈希→明文）与反向（明文→哈希）查询功能。

贡献与验证接口：用于用户提交哈希-明文对，以及对他人提交的数据进行社区确认。

桌面端专用接口：为桌面端程序设计的专用提交接口，用于区分数据来源并赋予不同初始状态。

2. 扩展功能接口

悬赏大厅接口：用于发布、查看、提交和完成悬赏任务。

积分商城接口：用于浏览商品、兑换商品及管理购买记录。

社区论坛接口：用于对哈希数据评论、在论坛发帖、回复及点赞。

二、核心API接口适配说明（桌面端）

以下为C#桌面端需要重点适配的API接口，适配点主要集中在请求标识、数据字段扩展和响应处理上。

1. 桌面端专用提交接口

路径：POST /api/tool/submit

适配说明：

请求头：C#桌面端必须设置特定的 User-Agent（DeepPwdDesktop/2.0 (Windows; C#)）和可选的 X-Device-ID（基于硬件信息的哈希值），以便后端识别为桌面端提交，从而获得 preliminary 的初始状态。

请求体：需包含 hash_type、hash_value、plaintext，并可选择性地携带 filenames 字段（压缩包内文件列表，逗号分隔）。

响应处理：处理后端返回的成功或失败状态，并根据返回信息进行界面提示。

2. 正向查询接口

路径：GET /api/search/hash-to-plain

适配说明：

请求参数：与网页端一致，包含 hash_type 和 hash_value。

响应处理：C#桌面端需要解析响应中的 filenames 字段。如果该字段不为空，则在查询结果界面中额外展示“压缩包内文件：”信息，例如显示为“readme.txt, secret.png”。

3. 反向查询接口

路径：GET /api/search/plain-to-hash

适配说明：

请求参数：与网页端一致，包含 plaintext。

响应处理：解析返回的哈希值列表，并在界面中清晰展示不同算法对应的哈希结果。

4. 用户认证接口

路径：POST /api/auth/login 与 POST /api/auth/register

适配说明：

实现方式：C#桌面端使用 HttpClient 发送包含用户名和密码的JSON请求。

Token管理：成功登录后，获取JWT Token，并将其安全地存储在本地（如使用 SecureString 或加密存储），并在后续所有需要认证的请求头中携带 Authorization: Bearer <JWT_TOKEN>。

5. 贡献与验证接口

路径：POST /api/contribute/confirm 与 GET /api/contribute/my-records

适配说明：

确认接口：用于桌面端用户对其他用户提交的数据进行社区确认。

查询贡献记录：用于桌面端用户查看自己的提交历史和积分获取情况，方便用户管理自己的贡献。

三、总结

通过以上适配，C#桌面端能够完全融入后端API体系。核心适配工作在于：

来源识别：通过固定 User-Agent 确保桌面端提交的数据能获得 preliminary 的初始状态和更高优先级。

数据扩展：支持提交和展示 filenames 字段，实现压缩包文件信息的传递与展示。

接口调用：使用 HttpClient 和异步编程模式，确保网络请求不阻塞UI，保持桌面端应用的流畅体验。
