密码侦探社网站项目文档 v2.1

项目概述

密码侦探社是一个面向互联网社区的压缩包密码检索平台。用户上传压缩包文件的哈希值（MD5/SHA1/SHA256 等）后，即可检索对应的解压密码；同时用户也可以主动贡献自己已知的哈希值与密码对，丰富数据库内容，帮助更多人解决问题。平台支持双向查询——通过哈希值查询密码，或通过密码反查对应的哈希值，实现数据的双向关联检索。

项目愿景：打造互联网上最全面、最便捷的压缩包密码检索社区，让每一位用户都能在几秒钟内找到需要的解压密码，同时鼓励知识共享与互助精神。

核心功能

哈希值查询密码

用户输入压缩包文件的哈希值，系统在数据库中匹配对应的解压密码并返回结果。若数据库中已有记录，用户可直接获取密码；若无记录，系统将提示暂无数据并引导用户贡献。

智能哈希类型识别：系统根据输入字符串的长度与字符集，自动识别哈希算法类型（MD5、SHA1、SHA256、CRC32 等），无需用户手动选择。

批量查询功能：支持用户粘贴多行哈希值或上传文本文件，系统一次性返回所有匹配结果，满足大量文件解密需求。

查询结果增强：

密码强度提示：显示密码强度指示（弱/中/强），辅助用户判断安全性。

来源信息展示：若贡献者提供了文件名或来源链接，将在结果中一并展示，提升可信度。

查询流程：用户输入哈希值 → 系统自动识别类型并校验格式 → 数据库匹配 → 返回密码结果（含强度与来源信息）或提示无数据。

密码反查哈希值

用户输入已知的解压密码，系统反向检索数据库中所有使用该密码的压缩包哈希值记录。适用于确认密码适用范围或查找特定密码关联文件。

结果聚合展示：当结果较多时，按哈希类型或贡献时间分组聚合（如“MD5 (120个结果)”），点击后展开详情，避免页面冗长。

高级筛选：支持按哈希类型、贡献时间范围等条件精确过滤，提升检索效率。

数据贡献与验证机制

用户可以主动提交哈希值与对应密码的关联数据，为社区数据库做出贡献。平台引入多端验证与社区共识机制，确保数据质量。

网页端提交（待验证机制）：

用户通过网页表单提交哈希值与密码对时，系统默认将其状态标记为 pending（待验证）。

处于待验证状态的数据，在普通用户查询时不予展示（或仅在结果页以灰色提示“待验证数据，仅供参考”）。

数据需经过社区投票验证或系统自动校验后，方可转为 verified（已验证）状态。

桌面端提交（桌面端验证机制）：

用户通过专属桌面客户端提交数据时，客户端在本地自动校验哈希算法合法性及密码格式。

校验通过后，桌面端在请求头中携带特殊的客户端签名（Client Signature）。

后端识别到合法签名后，直接将数据状态标记为 desktop_verified（桌面端已验证）。

desktop_verified 状态的数据具有更高的可信权重，在查询结果中优先展示，并附带“桌面端可信认证”专属标识。

本地哈希计算工具：集成基于 WebAssembly 的本地计算工具，用户拖拽文件至网页即可在浏览器端完成哈希计算，无需借助第三方软件，大幅降低贡献门槛。

贡献模板与规范：提供标准化填写模板与指南，鼓励补充上下文信息（如来源、加密方式等）。

贡献预览：提交前提供预览页面，确认信息无误后再写入数据库，防止误操作。

格式校验与去重：系统自动校验哈希格式合法性、密码长度（1-256 字符），并实时检查重复提交。

贡献流程：用户填写/拖拽文件 → 本地计算或手动输入 → 系统校验格式与去重 → 预览确认 → 写入数据库 → 返回贡献成功与积分奖励。

社区共识验证（Crowdsourced Validation）

平台引入社区投票验证模式，无需管理员人工审核，利用群体智慧实现数据的“自我净化”。

查询反馈：普通用户在查询到密码并成功解压后，可点击“验证成功”；若解压失败，可点击“密码错误”。

动态状态流转：系统根据社区反馈动态调整数据状态。例如：当一条 pending（待验证）数据获得 3 个以上的“验证成功”反馈，且无“密码错误”反馈时，系统自动将其提升为 verified（已验证）。反之，若收到 3 个以上的“密码错误”反馈，则自动标记为 rejected（已拒绝）或降级。

防刷票与恶意攻击防护：为防止恶意用户刷票篡改数据，系统需引入防刷机制。例如：同一 IP、同一账号在短时间内的反馈仅计算一次；引入“用户信誉分（Reputation）”，高等级贡献者的反馈权重更高。

激励相容：只有当用户反馈被系统判定为“正确”时（例如：社区多数认为成功，或者该数据本来就是高可信度数据），用户才能获得积分或信誉分奖励。

自动熔断机制：如果某条数据的 fail_votes 短时间内激增，系统可自动将其隐藏，并触发管理员告警，防止恶意数据污染数据库。

批量哈希值上传

支持用户通过文件上传（CSV/JSON 格式）批量导入哈希值与密码数据，适用于拥有大量数据的贡献者。

异步任务处理：大批量上传任务自动进入后台队列，立即返回任务 ID，避免页面长时间等待。

任务进度追踪：用户中心提供“我的任务”页面，实时查看处理进度（排队中/处理中/已完成/失败）及最终统计报告（成功数、失败数、重复数）。

标准模板下载：提供 CSV/JSON 标准模板文件下载，确保上传格式规范。

用户系统与积分

注册用户可获得积分激励，构建活跃的贡献者生态。

积分获取多元化：

核心贡献：成功贡献数据获得主要积分奖励。

日常活跃：每日签到、完善个人资料、参与社区讨论等行为可获得少量积分。

信誉分系统（Reputation）：

初始信誉分为 0。贡献高可信度数据、正确参与社区投票可提升信誉分。

恶意提交错误数据或恶意刷票将扣除信誉分。

高等级信誉分的用户，其社区投票权重更高，且享有更多平台权限。

成就徽章系统：除等级外，增设荣誉徽章，如“首日贡献”、“百次贡献者”、“哈希大师”、“火眼金睛”等，展示于个人主页，增强荣誉感。

等级与权限体系：

新手侦探（0-100 积分）

资深侦探（100-500 积分）

首席侦探（500+ 积分）

不同等级享有不同的查询频次、API 调用额度及高级功能权限。

积分消耗场景：

解锁高级功能（批量查询、API 调用额度）。

悬赏任务：用户可发布悬赏，使用积分奖励其他用户协助查找特定哈希值密码。

技术架构

前端架构

前端采用 Vue 3 + TypeScript 技术栈，使用 Vite 作为构建工具。UI 组件库选用 Element Plus，确保界面风格统一且交互友好。路由管理使用 Vue Router，状态管理使用 Pinia。页面设计遵循响应式原则，兼容 PC 与移动端访问。

核心页面模块：首页（搜索入口与数据统计展示）、查询结果页、贡献数据页、用户中心页（个人资料、积分管理、任务追踪）、排行榜页（贡献者排行与数据统计）、社区论坛。

后端架构

后端采用 Python FastAPI 框架，提供 RESTful API 接口。

任务队列：引入 Celery + Redis 作为消息代理，处理批量导入、邮件发送、悬赏结算等耗时任务，保障 API 响应速度。

缓存策略：

热点数据缓存：高频查询哈希值使用 Redis 缓存，设置合理过期时间。

布隆过滤器：查询前使用布隆过滤器快速判断哈希值“一定不存在”或“可能存在”，减轻数据库压力。

搜索引擎：集成 Elasticsearch，支持哈希值与密码的高效全文检索、模糊匹配及 ngram 分词，提升反查灵活性。

内容审核：集成自动化文本审核 API，过滤恶意、色情或广告内容。

API 接口设计遵循 REST 规范，主要接口包括：查询接口（GET /api/search）、贡献接口（POST /api/contribute）、批量导入接口（POST /api/batch-import）、用户注册/登录接口（POST /api/auth）、积分查询接口（GET /api/credits）、排行榜接口（GET /api/ranking）、API Key 管理接口、投票反馈接口（POST /api/vote）。

桌面端架构

桌面端不仅是一个上传工具，更是一个本地验证器。

推荐技术：Tauri (Rust + Vue/React) 或 Electron。

核心逻辑：桌面端在本地完成文件读取、哈希计算、格式校验，然后仅将“计算结果+客户端签名”发送给后端，大幅降低后端压力并提高数据准确性。

数据存储与索引

核心数据表设计：

hash_password 表：id、hash_value（统一小写存储）、hash_type、password、description、contributor_id、verify_status（枚举：pending/verified/desktop_verified/rejected）、verify_source（如 web_form/desktop_client_v1.0）、client_signature、success_votes（成功验证票数）、fail_votes（失败报错票数）、created_at、updated_at。

vote_feedback 表：id、hash_password_id（关联的哈希密码记录 ID）、user_id（投票用户 ID）、vote_type（枚举：success/fail）、created_at。

users 表：id、username、email、password_hash、credits、level、badges、reputation_score（用户信誉分）、created_at。

contributions 表：id、user_id、hash_password_id、contribution_type、created_at。

tasks 表：id、user_id、task_type、status、progress、result_report、created_at。

索引策略：哈希值字段建立 B-Tree 索引加速精确查询；密码字段建立全文索引支持模糊检索与反查。

安全与防护

数据安全：所有用户密码使用 bcrypt 加盐哈希存储，绝不存储明文；HTTPS 全站加密传输；定期备份数据库。

访问控制：API 接口实施分层 Rate Limiting（未注册 20次/小时，注册 100次/小时，高级 500次/小时）；敏感操作（批量导入、API Key 生成）需二次身份验证。

API Key 管理：支持用户生成、查看、删除个人 API Key，并自定义调用限额与权限。

操作审计：记录登录、修改密码、批量导入、积分变动等敏感操作日志，便于安全审计。

内容安全：自动化审核 + 人工复审机制，确保社区内容合规。

功能模块详细设计

首页与搜索模块

首页设计以简洁高效为核心，突出搜索功能入口。

搜索区域：顶部品牌标识与导航栏，中央搜索框支持“哈希查密码”与“密码查哈希”模式切换。

智能引导：

搜索历史：登录用户展示个人近期搜索记录。

热门搜索：展示全站高频查询词，辅助发现热门资源。

动态数据看板：实时滚动展示数据库总条目数、今日新增数、活跃贡献者数，增强社区活力感。

新手引导：首次访问用户弹出简洁浮层，介绍核心功能与贡献流程。

社区氛围：底部展示最新贡献记录与热门查询排行榜。

查询结果展示

查询结果页面展示匹配到的哈希值与密码记录列表。

信息展示：每条记录包含哈希值（部分遮挡）、类型标识、密码（默认遮挡）、强度提示、来源描述、贡献者昵称、贡献时间。

信任度可视化：在密码旁边展示一个“信任度进度条”或“点赞/踩”的数字徽标。例如显示“ 128 | 2”，让用户直观判断该密码的可靠性。

桌面端验证标识：在密码旁边展示一个带有盾牌图标的“桌面端可信”标签（如使用绿色高亮）。

待验证提示：如果系统允许展示待验证数据，使用橙色警告图标，并标注“ 社区贡献待验证”。

交互优化：

一键复制：点击密码旁按钮，视觉反馈“已复制”。

结果页反馈按钮：在每条密码结果旁增加醒目的“ 验证成功”和“ 密码错误”按钮。点击后需有明确的动画反馈（如按钮变色、弹出“感谢您的反馈”提示）。

结果导出：支持将当前查询结果导出为 TXT 或 CSV 文件。

排序与分页：支持按匹配度、时间、热度排序，分页浏览。

无结果引导：友好提示暂无数据，并引导用户贡献或发布悬赏。

贡献数据模块

贡献表单字段：哈希值（必填，支持自动识别或拖拽计算）、密码（必填）、压缩包描述（选填）、哈希类型（自动识别或手动选择）。

校验规则：哈希格式合法性、密码长度限制、实时去重检查。

预览确认：提交前展示完整信息预览，确认无误后提交。

成功反馈：提交成功后显示积分奖励详情，并鼓励继续贡献或查看贡献历史。

用户中心模块

用户中心包含个人信息、积分等级、贡献历史、查询历史、任务管理五大板块。

个人信息管理：修改昵称、头像、邮箱等基础信息。

积分与等级：展示当前积分、等级徽章、成就徽章墙、积分变动记录。

信誉分展示：展示当前信誉分及信誉等级，说明信誉分的作用。

贡献影响力：图表展示贡献趋势、被查询次数、帮助人数，增强成就感。

贡献历史：时间线形式展示所有提交记录及审核状态。明确展示每条数据的当前验证状态（待验证 / 桌面端验证 / 已验证），让用户清晰了解自己贡献数据的流转进度。

我的反馈：记录用户参与的社区投票历史，展示通过正确投票获得的信誉分和积分奖励。

查询历史：记录近期搜索行为，方便回溯。

我的任务：查看批量导入、悬赏等异步任务的进度与结果报告。

社区论坛

板块划分：解密技巧分享、疑难压缩包求助、工具资源推荐、站务公告。

互动机制：支持点赞、评论、采纳最佳答案，优质内容可获积分奖励。

页面设计规范

视觉风格

整体视觉风格以“侦探/解密”主题为核心，采用深色系背景搭配亮色高亮元素，营造神秘且专业的氛围。

主色调：深蓝灰色（#1A2332）为背景主色，明亮的琥珀金色（#F0B429）作为强调色与 CTA 按钮色，冷白色（#E8ECF1）作为正文文字色。

辅助色：成功绿（#4CAF50）用于查询成功状态，警告橙（#FF9800）用于提示信息，错误红（#F44336）用于错误状态。

图标与插图

图标使用线性风格，贴合侦探主题：放大镜（搜索）、钥匙（密码）、指纹（哈希值）、锁（加密）、盾牌（安全）、奖杯（成就）。首页使用一张主题插图（侦探手持放大镜审视密码锁），以 SVG 格式实现，确保加载速度与视觉一致性。

响应式设计

适配三种主流屏幕尺寸：

PC 端（≥1200px）：双栏布局，左侧导航 + 右侧内容区。

平板端（768px-1199px）：单栏布局，导航折叠为侧边栏。

移动端（<768px）：全宽单栏布局，导航变为底部 Tab 栏。

搜索框在所有尺寸下均保持居中突出展示，确保核心功能优先级不变。

开发计划

第一阶段：基础功能开发

搭建项目基础框架，完成数据库设计与初始化。实现核心查询功能（哈希查密码、密码查哈希），开发首页搜索界面与结果展示页。实现用户注册与登录功能，建立基础数据表与索引。完成 API 基础接口开发与单元测试。

第二阶段：社区功能与验证机制开发

开发用户贡献数据功能（单条提交、本地计算、批量导入），实现网页端待验证与桌面端验证机制。实现积分系统、等级体系、信誉分系统与成就徽章系统。开发用户中心页面（个人资料、贡献历史、积分管理、任务追踪、我的反馈），实现排行榜功能。集成 Elasticsearch 搜索引擎优化查询性能，添加自动化内容审核机制。上线社区论坛基础版本。

第三阶段：优化与扩展

性能优化与安全加固：API 限流策略完善、查询缓存与布隆过滤器优化、数据备份机制建立、操作日志审计系统上线。UI 细节打磨与交互体验优化，移动端适配完善。开放 API 服务与开发者门户建设。浏览器插件开发与测试。

数据安全与隐私

数据安全策略：用户密码采用 bcrypt 加盐哈希存储，绝不存储明文。查询结果中的密码默认遮挡显示，需用户点击确认后方可查看原文。API 接口实施分层 Rate Limiting。敏感操作需二次身份验证。
