# WP5-I11 依赖与运行环境升级实施计划

> **执行说明：** 按步骤实施，先修复供应链高危依赖，再升级同主版本依赖，并在发布前完成锁文件、静态检查、测试、构建与 Staging 验证。

**目标：** 修复前端锁文件中的高危 `nanoid` 解析版本，并将可低风险升级的前端依赖、pnpm 与本地/CI 运行时版本基线显式统一。

**范围与原则：**

- 仅升级已验证兼容的同主版本依赖；不将 Tailwind 4、Vite 8、Vitest 4、Pinia 4、Vue Router 5、TypeScript 7 等破坏性主版本迁移混入本轮。
- Python API 继续以 `>=3.12` 与既有上界约束为兼容范围；部署镜像统一为 Python 3.12.13。
- Node.js 统一为 22.23.1，pnpm 统一为 11.19.0；Docker、GitHub Actions 与开发者版本文件以相同基线表达。
- 更新后的锁文件必须消除 `nanoid@<3.3.18` 的高危审计结果。

---

## 验收标准

- `pnpm audit --prod --audit-level=high` 无高危漏洞。
- 新锁文件不再包含 `nanoid@3.3.17`。
- 前端 lint、类型检查、测试与构建通过；API 静态检查、迁移往返与测试通过。
- CI、Docker 与本地版本文件的 Node/Python/pnpm 基线一致。
- Git Data API 远端树与本地发布提交树一致，Staging 运行本次修订镜像。
