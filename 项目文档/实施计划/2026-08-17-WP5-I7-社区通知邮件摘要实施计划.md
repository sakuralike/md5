# WP5-I7 Community Notification Email Digest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build durable, preference-aware, minimum-disclosure community email digest delivery through the existing notification gateway and SMTP implementation.

**Architecture:** Notification creation will independently enqueue existing in-app events and new email-digest batch items in the same database transaction. Because the durable notification fact can support either channel, in-app list, unread, read and SSE paths will filter against the current `in_app_enabled` preference. A Celery task will claim mature UTC-window digest batches, revalidate each linked notification, suppress invalid entries and exclude superseded delivery versions, and invoke a stable-idempotency gateway call for the remaining summary. Existing Admin metrics will expose aggregate batch states only.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2, Alembic, Celery, SMTP/EmailMessage, pytest, Vue 3, TypeScript, Shadcn-Vue, Tailwind CSS, pnpm.
