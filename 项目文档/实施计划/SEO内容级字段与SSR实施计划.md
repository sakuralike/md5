## 1. 背景与目标

首阶段 SEO 已完成站点级配置、运行时页面元信息、robots 和根路径 sitemap。当前 Web 仍是 Vue SPA，动态社区页面尚未具备稳定的内容级 SEO 字段、公开状态判定和 SSR/预渲染收录保证。

本计划用于在继续开发前固定以下决策：

1. 哪些内容可以公开展示、进入 sitemap 和被搜索引擎索引。
2. 哪些角色可以编辑内容级 SEO 字段，以及如何审计和并发控制。
3. SEO 字段如何校验、回退和投影，避免泄露私密内容、内部字段或脚本。
4. 在当前 SPA 约束下，如何分阶段引入 SSR/预渲染，而不把浏览器运行时 head 误称为 SSR。
5. 是否以及何时接入百度普通/快速收录，如何保护推送凭据。

## 3. 公开资格与 sitemap 收录策略

### 3.1 统一原则

只有明确列入公开白名单、且通过内容状态与权限判定的稳定 URL 才能进入 sitemap。以下内容永远不得进入 sitemap 或产生可索引的 canonical：

- 私密群组、私密帖子、隔离内容和仅成员可见内容；
- 已删除、已移除、未发布、审核未通过或状态不明确的内容；
- 搜索结果、筛选结果、分页查询参数、哈希片段、会话和管理端 URL；
- 需要登录、申请加入、临时授权或依赖请求用户身份才能成立的页面；
- 无法得到稳定公开 slug/id 或无法在目标环境生成合法 canonical 的页面。

### 3.2 各页面资格矩阵

| 页面 | 最低收录条件 | 默认不收录条件 | 说明 |
|---|---|---|---|
| 帖子 | `status=PUBLISHED`；所属板块有效；无群组或群组 `ACTIVE` 且可公开发现；正文/标题可公开读取 | `REMOVED`、草稿、审核未通过、私密群组、隔离状态、权限判定异常 | 复用社区服务的公开读取条件，不复制 SQL 权限逻辑 |
| 群组 | `status=ACTIVE` 且 `visibility=PUBLIC`；slug 稳定；公开详情接口无需登录 | `PRIVATE`、`APPROVAL`（在审批收录策略确认前）、`INACTIVE`、slug 冲突或状态异常 | 审批群组可继续被授权用户浏览，但先不自动进入 sitemap |
| 用户 | 账号有效；公开资料存在且允许公开；公开资料页路由无需登录 | 用户停用/删除、资料关闭、隐私策略不允许公开、内容只剩私密或隔离数据 | 资料页和帖子列表均需通过现有公开投影 |
| 板块 | 板块有效且有明确公开路由；管理员确认其可被搜索引擎发现 | 隐藏/停用板块、内部板块、无稳定公开 URL | 未确认前不新增动态 sitemap URL |
| 文章/标签 | 对应实体、路由、状态和公开策略全部落地 | 当前没有实体或公开路由 | 延后，不以规划代替实现 |

上述矩阵是保守默认值。任何放宽（例如允许 `APPROVAL` 群组收录）必须先补充规格、权限测试、sitemap 测试和验收记录。

## 4. SEO 字段设计

### 4.1 建议字段

对已确认支持的内容实体增加独立 SEO 投影字段；字段命名建议保持一致：

| 字段 | 类型/限制 | 空值行为 |
|---|---|---|
| `seo_title` | 可空字符串；建议最多 120 个 Unicode 字符 | 回退到内容标题，再由站点标题连接符拼接 |
| `seo_description` | 可空字符串；建议最多 320 个 Unicode 字符 | 回退到安全截断后的公开摘要 |
| `seo_keywords` | 可空字符串或规范化字符串数组；建议最多 20 个词、总长受限 | 不输出 keywords 或使用站点级默认值，二者需在 API 合同中固定 |
| `seo_canonical_path` | 可空站内绝对路径；禁止外部 Origin、查询串、哈希和控制字符 | 回退到服务端生成的稳定公开路径 |
| `og_image_url` | 可空、经 Origin/协议白名单校验的图片 URL | 回退到站点默认图片；禁止内部文件、带凭据 URL |

本字段不存储密码、令牌、SMTP 凭据、搜索推送密钥或任何内部审计信息。`canonical` 不允许通过任意外部 URL 造成跨站注入或 SEO 劫持。

### 4.2 校验与归一化

- 统一执行 trim、Unicode 控制字符拒绝、长度限制和空值归一化。
- 标题、描述、关键词禁止 HTML、脚本协议、事件属性和未批准模板表达式。
- 关键词输入支持前端友好格式，但服务端必须最终解析、去重并限制数量和总长度。
- canonical 仅允许合法站内路径；Origin 由受信配置生成，不信任请求 Host。
- OG 图片只允许受信 HTTPS Origin 或经明确批准的相对资源；禁止用户名、密码、签名密钥出现在 URL 中。
- 读取接口只返回当前用户有权看到的 SEO 投影；无公开资格时不得通过 SEO 字段泄露标题、摘要或作者隐私。
- 任何字段保存都应使用幂等键、审计摘要和乐观并发版本，避免重复写入和覆盖他人修改。

## 5. 权限、接口与审计

### 5.1 编辑权限

| 对象 | 可编辑角色 | 约束 |
|---|---|---|
| 帖子 | 帖子作者；所属群组授权版主/群主；授权管理员 | 仍受帖子编辑窗口、审核和群组权限限制；不能借 SEO 字段发布不可见内容 |
| 群组 | 群主；授权管理员 | 群组状态/可见性变化时重新计算 SEO 资格 |
| 用户资料 | 用户本人；授权管理员 | 不允许他人通过 SEO 字段修改公开资料或绕过隐私策略 |
| 板块/分类 | 授权管理员 | 需要单独的板块管理接口和公开路由确认 |
| 文章/标签 | 暂无 | 实体和权限确认前不实现 |

### 5.2 建议 API 合同

第一阶段实现时，优先将 SEO 作为已有详情响应中的受控 `seo` 投影，并让服务端统一计算 `indexable` 与 `canonical`：

```json
{
  "seo": {
    "eligible": true,
    "indexable": false,
    "title": "公开标题",
    "description": "公开摘要",
    "keywords": [],
    "canonical_path": "/community/posts/123",
    "og_image_url": null
  }
}
```

- `eligible` 表示资源通过公开资格矩阵；`indexable` 还必须满足 SSR/预渲染和公开 sitemap 验收。当前 Vue SPA 阶段允许返回安全的 `eligible=true/indexable=false` 投影，但不得把动态详情切换为可索引。
- `eligible=false` 时只返回空的安全投影，不得返回内部拒绝原因、审核备注或权限细节。
- 写入接口必须使用现有身份与资源授权链；推荐使用 `PATCH /.../{id}/seo`，避免把 SEO 写入混入不相关的状态变更。
- 写接口需支持 `Idempotency-Key` 与 `If-Match`/版本号；冲突返回明确的并发错误，不能静默覆盖。
- 所有写入记录资源、操作者、字段摘要、结果和关联请求 ID；日志中不得记录完整敏感内容。
- API 合同、错误码和权限矩阵在编码前同步到 `packages/api-contract`、后端测试和文档变更记录。

## 6. 动态 sitemap 设计

动态 sitemap 只能消费“公开资格服务”的结果，不得直接查询原始表后自行判断权限。建议分两步：

1. 先提供分页/流式的公开 SEO URL 发现服务，返回稳定 URL、`lastmod` 和必要的资格摘要。
2. 在 robots/sitemap 路由中使用该服务，加入上限、超时、缓存、ETag 和失败安全回退；生成失败时不输出不确定 URL，必要时回退到合法空 sitemap。

推荐路径保持稳定且不含查询参数：

- `/community/posts/{postId}`
- `/community/groups/{slug}`
- `/community/users/{username}`

任何新路径都必须同时加入公开路由白名单、服务端资格测试、XML 合法性测试和浏览器验收。首轮不改变现有“仅根路径和社区首页可索引”的策略，直到内容级资格服务和 SSR/预渲染方案完成验收。

## 7. SSR/预渲染决策

当前 Web 是 Vue SPA，浏览器运行时更新 head 的结果不能等同于搜索引擎稳定获取的 SSR/预渲染 HTML。因此分两阶段处理：

### 7.1 Task 7-A：先做服务端元信息发现

- 建立公开资格服务与受控 `seo` 投影。
- 详情接口返回安全的 `seo` 数据，Web 继续使用运行时 head 作为兼容回退。
- 在没有 SSR/预渲染之前，不把动态内容切换为可索引，也不修改首阶段 sitemap 白名单。
- 以真实浏览器和 API 契约测试验证权限边界、重复标签清理和异常回退。

### 7.2 Task 7-B：另行评审 SSR 或预渲染适配器

在单独评审中选择以下一种，并补充运行手册与目标环境证据：

- **SSR**：由服务端为公开 URL 生成首屏 HTML 与 head，要求缓存隔离、用户身份不进入公共缓存、失败回退安全。
- **预渲染**：仅对稳定公开内容生成静态页面，要求内容变更触发失效/重建，失败不能保留过期的私密页面。

无论选择哪种方案，都必须覆盖 canonical、Open Graph、robots、权限错误、内容删除后的失效、缓存键、超时和回滚。没有目标环境验证前，不宣称“已支持 SSR/预渲染收录”。

## 8. 百度普通/快速收录：暂缓接入

本轮不接入百度推送。若后续确认接入，必须先完成：

1. 使用服务器密钥管理或部署环境 Secret 注入，禁止明文写入数据库、前端包、Markdown、镜像层和日志。
2. 为普通/快速收录分别定义最小权限、域名绑定、调用配额、超时、重试和退避。
3. 建立密钥轮换、撤销、泄露响应、操作审计和按环境隔离流程。
4. 先以 dry-run 和合成 URL 验证，不允许把私密、审批未确认或删除内容推送给搜索引擎。
5. 增加幂等、防重复、失败队列、人工暂停开关和可观测指标；正式启用需单独批准。

## 10. 回滚与发布边界

- 阶段 7-A 无数据库迁移和可逆数据写入；回滚时移除详情响应 `seo` 投影并恢复旧 API 镜像即可，robots/sitemap 继续保持安全默认。
- 后续实现应按阶段独立提交和部署；若公开资格判断或 sitemap 生成异常，默认关闭动态内容索引并保留合法空 sitemap。
- 字段迁移回滚必须使用发布前数据库备份，不能把已经写入的内容截断为旧长度或旧类型。
- SSR/预渲染回滚应先切回 SPA 安全的 `noindex` 策略，再撤除缓存/静态产物，避免私密页面继续被公共缓存提供。
