# 桌面插件开发者升级方案

## 目标

建立从插件版本创建、升级开发、审核、发布、客户端更新到回滚的完整流程。升级必须保持现有插件可运行、版本内容不可变、权限变化可追踪，并且不能通过更新包绕过静态审核、动态审核或管理员批准。

## 版本规则

- 插件版本使用严格 SemVer `主版本.次版本.补丁版本`。
- 同一插件的已冻结版本号和制品摘要不可覆盖；升级必须创建新的版本记录和新的 `.pdpkg`。
- 补丁版本只修复兼容性或缺陷，不得新增权限、改变签名密钥或改变命令输入语义。
- 次版本可以增加向后兼容的命令、可选字段和资源，但新增权限必须重新申请和确认。
- 主版本用于不兼容的命令、Schema、数据格式或宿主能力变化，必须提高 `host.min_version` 或协议范围并提供迁移说明。
- 官方插件与第三方插件使用相同版本规则；官方身份不跳过审核。

## 开发者升级流程

1. 从当前已发布版本复制 Manifest、命令 Schema、SBOM 和兼容性测试。
2. 修改代码并创建新的 SemVer 版本；不得修改旧版本制品或签名文件。
3. 使用开发者 Ed25519 私钥签名，重新生成逐文件 SHA-256 和 CycloneDX 1.5 SBOM。
4. 在 `source/` 放入与可执行制品对应的源码；源码、Manifest、Schema、SBOM 和二进制必须来自同一构建提交。
5. 运行本地包验证、协议合规、权限差异、升级/回退和 AppContainer 测试。
6. 上传到隔离区并 finalize；服务端重新计算大小、摘要、Manifest 和签名。
7. 提交自动静态/供应链审核；失败时在同一版本修复并重新提交，已冻结制品不原地替换。
8. 自动审核通过后由管理员复核源码、权限差异、运行证据和发布说明，再批准并发布到稳定通道。

## 客户端升级策略

- 宿主只从已发布、未撤销、兼容当前宿主和架构的版本获取下载票据。
- 安装前显示当前版本与目标版本、开发者、权限差异、风险等级、审核时间和发布说明。
- 无新增权限、无密钥变化且非主版本升级的补丁更新，可以由用户确认后直接更新。
- 新增权限、开发者签名密钥变化、风险等级升高或主版本升级必须再次确认；不能静默授予新权限。
- 下载后验证制品大小、SHA-256、开发者签名、平台审核签章和撤销列表，再进行原子安装。
- 新版本健康检查失败时保留旧版本并自动回退；运行期连续失败达到阈值时停用插件并写入本地日志。
- 用户数据只存放在插件私有存储目录；升级不删除私有数据，卸载和撤销也不隐式删除数据。

## 兼容性与迁移

- 命令 ID、已有字段名称和字段类型在补丁/次版本中保持兼容；删除或改义字段必须进入主版本。
- 插件私有存储键采用稳定前缀。需要迁移时，在升级命令中执行幂等迁移并保留旧键直到新版本健康检查完成。
- `ui:window` 仅允许插件在自身 AppContainer 进程创建 WPF 窗口；不得把第三方 DLL、XAML 或窗口句柄加载/注入到宿主主进程。
- 平台 API 能力必须通过宿主 Broker；Scope、用户授权和版本批准状态在每次调用时重新校验。
- 宿主新增 Broker 方法必须保持旧方法行为，协议 Schema 通过后才能进入稳定版本；宿主移除能力前至少保留一个兼容窗口并阻止不兼容版本安装。

## 发布通道与回滚

- `stable`：经过完整自动审核、人工批准和平台签章，面向普通用户。
- `canary`：仅用于合成账号或受控内部安装，必须与 stable 使用不同发布记录和下载策略。
- 每次发布保留上一稳定版本、制品摘要、平台签章和审核证据；回滚通过发布记录切换，不重写版本数据。
- 紧急撤销立即从公开目录和下载票据中移除目标版本；客户端启动和定期刷新撤销列表后停用目标版本。
- 回滚或撤销不跳过权限校验、签名校验和本地健康检查。

## 开发者交付检查表

- [ ] SemVer、宿主版本范围和协议范围明确
- [ ] 权限差异已说明，新增权限有用户确认路径
- [ ] `.pdpkg`、逐文件 SHA-256、Ed25519 签名和 SBOM 来自同一提交
- [ ] `source/` 源码可供管理员查看且与制品匹配
- [ ] C# / Go / Rust / Python（如适用）PDPP 合规测试通过
- [ ] AppContainer、资源限制、崩溃、超时和撤销场景通过
- [ ] 升级、迁移、健康检查、失败回退和卸载数据保留通过
- [ ] 自动审核、人工审核、发布和回滚证据完整
