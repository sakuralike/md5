# 密码侦探社下一阶段开发计划（2026-08）

> - 计划日期：2026-08-03
> - 建议执行窗口：2026-08-04 至 2026-08-21（单人、14 个工作日）
> - 计划性质：M4 收口与 M5 准入冲刺
> - 规格基线：[密码侦探社项目规格说明书 v3.0](./密码侦探社项目规格说明书-v3.0.md)
> - 当前证据：[项目整体完成度审计（2026-08-03 复核）](../docs/development/2026-08-03-completion-audit.md)

## 1. 阶段目标

下一阶段不再扩展新的通知渠道、分析模型或运营功能，而是集中关闭影响 MVP 验收的三个 P0 业务闭环，并建立进入 M5 的自动化门禁：

1. 普通用户可以完成账号资料、安全控制、授权记录和隐私请求。
2. 管理员可以查看真实仪表盘与审计数据，并在最小权限、二次确认和不可变审计约束下处置用户与配置。
3. 账号申诉、案件状态、候选状态和结果通知形成可追踪、可重试、可审计的闭环。
4. 核心 Web/Admin 旅程进入浏览器 E2E，统一检查脚本在支持的 Windows PowerShell 环境可稳定运行。

本阶段完成后，目标是将项目从“可内部演示、核心切片可运行”推进到“P0 业务闭环基本完成、具备 M5 系统验收入口”。

## 2. 范围边界

### 2.1 本阶段包含

- 用户资料、密码修改、用户 TOTP、会话管理、邮箱验证和密码重置页面。
- 授权声明记录、揭示历史、数据导出申请、账号删除申请及状态查询。
- 管理仪表盘、审计查询/导出、用户状态与角色、封禁/解封、版本化系统配置。
- 管理员高风险操作的近期再认证、MFA、原因码、幂等和不可变审计。
- 账号申诉、案件与候选状态编排、结果通知、重开与升级规则。
- Playwright 核心旅程、对象级权限测试、基础安全扫描和恢复冒烟入口。

### 2.2 本阶段不包含

- 新增短信、企业微信、钉钉等通知渠道；继续复用现有 SMTP、Webhook 和 Outbox。
- 跨候选关联图谱、自动处罚、批量贡献、论坛、商城、公开 API、移动 App 或 AI 猜密。
- 正式生产域名、真实 SMTP 服务商、Authenticode、CDN、预生产和灰度发布；这些保留在 M5/P2。
- 大规模性能调优和完整灾难恢复认证；本阶段只建立门禁、脚本和首次演练基线。

**建议工期：0.5～1 个工作日**

- 将当前 Tailwind CSS 3、Shadcn-Vue 初始化和 Web 简白科技感视觉改造作为独立变更集复核。
- 确认用户 Web 的毛玻璃、四套内置背景和会话级本地图片背景不会影响 Admin 样式。

- Web/Admin 类型检查、单元测试和生产构建通过。

- 视觉改动、Shadcn-Vue 环境与完成度文档可以独立评审和回滚。

## 6. 工作包 N1：用户账号与隐私中心

**建议工期：4 个工作日**
**优先级：P0**

### 6.1 后端与数据

- 在现有认证模块上完善个人资料修改、密码修改、用户 TOTP 启用/确认/禁用。
- 复用已存在的邮箱验证、重新发送验证邮件、忘记密码和重置密码接口，不重复创建认证流程。
- 新增揭示历史查询，只返回归档指纹摘要、时间、结果状态和审计引用，不返回历史明文密码。
- 建立授权声明记录，保存声明版本、用途、确认时间、来源和撤回状态，不保存真实秘密。
- 建立数据导出申请和账号删除申请状态机；导出任务异步执行，下载采用短时凭据，删除流程保留法定审计记录并清除可删除业务数据。
- 所有写操作接入幂等、速率限制、会话撤销和不可变审计。

### 6.2 Web 页面

新增或完善以下路由：

- `/verify-email`
- `/forgot-password`
- `/reset-password`
- `/account/profile`
- `/account/security`
- `/account/activity`
- `/account/privacy`

页面沿用当前简白科技感与毛玻璃视觉体系，覆盖加载、空状态、失败、重试、移动端和键盘操作。

### 6.3 拟新增或完善的 API

| 方法 | 路径 | 用途 |
|---|---|---|
| `PATCH` | `/me/profile` | 修改允许编辑的个人资料 |
| `POST` | `/me/security/password/change` | 验证旧密码后修改密码并撤销其他会话 |
| `POST` | `/me/security/totp/setup` | 创建用户 TOTP 待确认配置 |
| `POST` | `/me/security/totp/confirm` | 确认启用 TOTP |
| `DELETE` | `/me/security/totp` | 经近期再认证后禁用 TOTP |
| `GET` | `/me/reveals` | 查询最小披露的揭示历史 |
| `GET` | `/me/authorization-declarations` | 查询授权声明记录 |
| `POST` | `/me/authorization-declarations` | 确认当前版本的授权声明 |
| `POST` | `/me/privacy/exports` | 创建数据导出申请 |
| `GET` | `/me/privacy/exports/{export_id}` | 查询导出状态和短时下载信息 |
| `POST` | `/me/privacy/deletion-requests` | 创建账号删除申请 |
| `GET` | `/me/privacy/deletion-requests/current` | 查询当前删除申请 |
| `POST` | `/me/privacy/deletion-requests/{request_id}/cancel` | 在允许窗口内撤销申请 |

具体命名在编码前通过 API 契约评审冻结；同类操作不得同时保留多个语义重复接口。

### 6.4 测试与验收

- API：成功、未认证、错误旧密码、弱密码、重复请求、跨用户访问、已撤销会话、TOTP 重放、导出过期和删除撤回边界。
- Web：服务层与组件测试覆盖所有状态；浏览器冒烟覆盖邮箱验证、重置密码、修改资料、启用 TOTP、撤销会话和创建隐私请求。
- 安全：响应与日志不得包含 TOTP 秘钥、重置令牌、历史明文密码、完整归档文件清单或其他用户数据。

### 6.5 出口条件

- 用户可独立完成账号安全和隐私请求，不依赖管理员手工改库。
- 密码修改、TOTP 禁用和删除申请均要求近期再认证；高风险操作产生不可变审计。
- 数据导出文件可验证归属、过期和一次性/短时访问策略。
- N1 新增 API、Web 页面、迁移和文档均有自动化测试。

## 7. 工作包 N2：管理员治理中心

**建议工期：4 个工作日**
**优先级：P0**

### 7.1 后端与数据

- 建立真实仪表盘聚合查询：查询量、命中率、贡献量、验证率、隔离量、错误率和队列积压。
- 建立审计事件列表、详情和 CSV 导出；默认脱敏，导出任务记录操作者、筛选条件、时间范围和制品摘要。
- 建立用户列表、详情、状态、角色和信誉摘要查询，以及受控封禁/解封操作。
- 建立版本化系统配置：草稿、校验、发布、回滚和生效时间；历史版本不可覆盖。
- 为危险操作增加近期再认证凭据：管理员密码/当前会话校验、TOTP、短时一次性操作令牌、受控原因码和 `Idempotency-Key`。
- 普通用户、低权限管理员和未完成 MFA 的管理员必须被服务端拒绝，不能只依赖前端隐藏按钮。

### 7.2 Admin 页面

新增或实化以下页面：

- 仪表盘：真实指标、时间范围、刷新状态和数据来源时间。
- 审计中心：筛选、详情、脱敏导出和导出记录。
- 用户与权限：列表、详情、状态、角色、封禁/解封和信誉时间线。
- 系统配置：版本列表、差异预览、校验、发布和回滚。
- 危险操作确认对话框：说明影响、输入原因、完成再认证并显示审计引用。

### 7.3 拟新增或完善的 API

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/admin/auth/reauth` | 生成短时、一次性、高风险操作凭据 |
| `GET` | `/admin/dashboard/summary` | 查询真实治理指标 |
| `GET` | `/admin/audit-events` | 按范围、操作者、事件和对象筛选审计 |
| `POST` | `/admin/audit-exports` | 异步创建脱敏审计导出 |
| `GET` | `/admin/users` | 查询用户列表 |
| `GET` | `/admin/users/{user_id}` | 查询用户治理详情 |
| `POST` | `/admin/users/{user_id}/ban` | 受控封禁并撤销会话 |
| `POST` | `/admin/users/{user_id}/unban` | 受控解封 |
| `PUT` | `/admin/users/{user_id}/roles` | 按最小权限更新角色 |
| `GET` | `/admin/settings/versions` | 查询配置版本 |
| `POST` | `/admin/settings/versions` | 创建不可变配置草稿 |
| `POST` | `/admin/settings/versions/{version_id}/publish` | 发布已校验版本 |
| `POST` | `/admin/settings/versions/{version_id}/rollback` | 创建回滚版本并发布 |

### 7.4 测试与验收

- 权限矩阵覆盖普通用户、审核员、运维管理员和超级管理员。
- 对象级越权、缺少 MFA、再认证过期、重复幂等键、并发封禁、非法角色提升和配置回滚冲突必须有测试。
- 审计导出测试验证脱敏、时间范围、数据归属、过期和下载审计。
- Admin 页面测试覆盖加载、空状态、错误、权限拒绝、危险操作取消/确认和服务端冲突。

### 7.5 出口条件

- 仪表盘不再使用硬编码演示数据。
- 管理员可检索审计并导出脱敏结果；任何导出本身也进入审计。
- 封禁会立即撤销目标用户会话；解封、角色变更和配置发布均可追踪且不可静默覆盖。
- 所有危险操作同时满足 RBAC、当前会话 MFA、近期再认证、原因、幂等和不可变审计。

## 8. 工作包 N3：案件编排与结果通知

**建议工期：3 个工作日**
**优先级：P0**

### 8.1 任务

- 扩展现有统一信任案件模型，支持账号申诉，并明确案件主体是候选、账号还是风险告警。
- 建立案件状态与候选/用户处置之间的显式编排，禁止通过前端连续调用多个无事务接口模拟状态机。
- 固化受控重开、升级、转派、解决和驳回原因；重复请求不得生成重复事件或重复通知。
- 复用现有事务 Outbox、SMTP 和 Webhook 投递能力发送处理结果，不新增通知提供商。
- 用户端显示案件时间线和最小披露的处理结果；Admin 显示编排结果、通知状态和审计引用。

### 8.2 状态与一致性要求

- 案件事件、候选/用户状态变更、积分/信誉补偿和通知 Outbox 必须在同一事务边界内提交，或采用可证明一致的补偿流程。
- 已关闭案件只能通过受控原因重开；升级和转派必须保留前后负责人、SLA 和 `request_id`。
- 通知模板不得包含候选密码、完整邮箱地址、TOTP 秘钥、访问令牌或内部签名材料。

### 8.3 出口条件

- 用户可以提交账号申诉并查看本人案件状态；不能查看他人案件。
- 管理员一次受控操作即可完成案件处置及相关状态编排，不产生部分成功的悬挂状态。
- 结果通知成功、失败、重试和人工重放均可审计，重复重放不重复发送已确认成功的通知。

## 9. 工作包 N4：M5 准入门禁

**建议工期：2～3 个工作日**
**优先级：P1，但作为本阶段出口门禁**

### 9.1 自动化与兼容性

- 引入 Playwright，覆盖 Web 注册/登录、邮箱验证、查询、揭示、贡献、用户中心、案件和退出主旅程。
- 覆盖 Admin 登录、TOTP、仪表盘、审计查询、用户封禁/解封、配置发布和案件处置主旅程。
- 为主要页面建立 1440 px 与移动端视觉快照；动态时间、随机 ID 和敏感字段必须稳定化或遮罩。
- 修复统一检查脚本在 Windows PowerShell 5.1 的语法兼容问题，或在脚本入口明确检测并提示 PowerShell 7；优先实现 5.1/7 双兼容。

### 9.2 首批安全与恢复门禁

- CI 增加依赖审计、Python/TypeScript SAST 和容器镜像扫描的基线任务；高危结果阻断，允许项必须有到期豁免记录。
- 生成首版 SBOM，并保留构建来源、依赖版本和制品摘要。
- 建立 SQLite/MySQL 迁移回滚、Redis 丢失、Worker 重启和数据库备份恢复的冒烟脚本或运行手册。
- 记录首次演练结果、实际 RPO/RTO、失败点和后续整改项；未实际执行的步骤不得标记通过。

### 9.3 出口条件

- 本地统一门禁和 CI 全部通过，新增浏览器 E2E 无不稳定重试依赖。
- P0 阻塞缺陷为 0；P1 高风险缺陷为 0，其他遗留项有负责人、截止日期和风险说明。
- 安全扫描无未豁免的高危问题；恢复冒烟有可重复命令和证据。
- 完成一次新的项目完成度复核，并决定是否正式进入 M5 第 12 周系统测试。

## 12. 全阶段完成定义

每个工作包必须同时满足：

- 需求与验收标准已在 Markdown 中明确，并能追踪到 v3.0 规格。
- API 契约、共享类型、迁移和权限矩阵同步更新。
- 代码经过评审；单元、集成、页面和必要的 E2E 测试通过。
- 安全与隐私影响已检查，日志和通知满足最小披露。
- 所有写操作具备幂等或明确的并发控制；危险操作具备再认证和不可变审计。
- 配置、运行手册、监控或故障处理说明随实现更新。

## 13. 阶段级验收清单
