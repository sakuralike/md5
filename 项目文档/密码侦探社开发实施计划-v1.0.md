# 密码侦探社开发实施计划 v1.0

- **计划基线：** 2026-08-01
- **交付目标：** 完成《密码侦探社项目规格说明书 v3.0》定义的 MVP
- **计划周期：** 14 周（含 2 周稳定与发布缓冲）
- **估算口径：** 基准团队 4.5 个全职当量；若仅 2 名开发者，建议调整为 22–26 周
- **当前执行计划：** [下一阶段开发计划（2026-08）](./密码侦探社下一阶段开发计划-2026-08.md)
- **最新工程增量：** WP4 第 27 次迭代已将真实 MySQL/Redis HA `target-observation` 能力报告强制绑定到 `target-execution` 封存包及 `evidence_set_sha256`；目标服务器正式 4 小时会话已于 2026-08-11 19:31:10（Asia/Shanghai）启动，MySQL/Redis 真实 HA 仍依赖外部目标平台。
- **当前工程估算：** 核心功能约 97%，本地自动化约 99%，综合研发约 89%，生产上线就绪约 76%。
- **当前发布治理：** 不要求人员签字，不要求桌面签名证书；发布由完整机器证据、制品大小/SHA-256、合法分发声明和自动 Go/No-Go 门禁决定。

## 1. 计划原则

1. 先交付“本地指纹计算→精确查询→贡献→本地验证→可信状态→揭示”的完整闭环。
2. 采用模块化单体和单仓库，避免在没有流量依据时引入多语言微服务、Kafka、Elasticsearch 或 Kubernetes。
3. 安全、合规、审计和可恢复性属于首版功能，不作为上线后的补丁。
4. 每个迭代均要求可演示、可测试、可部署；不以“代码完成”替代验收完成。
5. 范围变更必须说明业务价值、人员成本、关键路径影响和需要移出的工作。

## 4. 阶段任务拆解

## 4.1 M0：需求、安全与体验基线（第 1 周）

### 工作项

- 评审 v3.0 规格并关闭“待产品负责人确认”参数中的阻塞项。
- 创建 ADR：技术栈、数据加密、令牌方案、桌面验证信任边界、首版压缩格式。
- 输出数据流图与威胁模型，覆盖密码揭示、贡献、回执、管理操作和备份。
- 完成核心页面低保真原型：主页、查询结果、贡献向导、用户中心、审核详情。
- 建立需求编号到测试用例的追踪矩阵。
- 明确服务条款、隐私政策、授权声明和举报/删除流程负责人。

### 出口条件

- MVP 与非 MVP 清单获得确认。
- 状态机、证据阈值、匿名可见性和每日揭示配额有书面决策。
- 高风险威胁均有控制措施或风险接受人。
- 原型覆盖桌面与移动 Web 的核心流程。

## 4.2 M1：工程基础与认证（第 2–3 周）

### 后端

- 初始化 FastAPI 模块化单体、SQLAlchemy、Alembic、配置与依赖注入。
- 建立 users、user_sessions、audit_logs、system_settings 基础表。
- 实现注册、邮箱验证预留、登录、刷新轮换、退出、会话撤销。
- 接入 Argon2id、RBAC、统一错误、request_id、结构化日志。
- 实现 Redis 分布式限流框架和数据库持久化幂等基础。

### Web 与管理端

- 初始化 Vue 3 + TypeScript 两个应用和共享设计令牌。
- 建立路由、Pinia、API 客户端、鉴权守卫、错误提示和基础布局。
- 完成注册、登录、退出、会话过期处理和个人安全页骨架。
- 管理端完成独立登录入口、角色路由和审计菜单骨架。

### DevOps/QA

- Docker Compose 启动 MySQL、Redis、API、Web、Admin 和 Worker。
- 建立 CI：格式化、Lint、类型检查、单元测试、镜像构建、依赖扫描。
- 建立开发、测试环境配置和种子数据策略；禁止真实密码进入测试环境。
- 建立迁移检查、测试报告和制品版本命名。

### 出口条件

- 新环境从空目录到可登录不超过 30 分钟。
- 刷新令牌重复使用可被检测并撤销会话族。
- 权限测试证明普通用户不能访问管理 API。
- CI 主分支全部通过，迁移可正向执行并有回滚说明。

## 4.3 M2：核心 Web 查询与贡献（第 4–6 周）

### 数据与后端

- 创建 archives、archive_fingerprints、password_candidates、submissions、points_ledger。
- 完成密码候选加密封装、密钥版本字段和不可写日志过滤器。
- 实现完整指纹识别、规范化、唯一约束、重复合并和幂等提交。
- 实现查询、遮挡、揭示、配额扣减和审计事件。
- 实现基础积分待结算与正式入账框架。

### Web 用户端

- 文件拖拽、分块 MD5/SHA-256 计算、进度、取消和大文件提示。
- 手工指纹输入、自动识别、格式错误定位。
- 查询结果卡片、可信状态、候选列表、遮挡、揭示、复制。
- 贡献向导：授权确认、候选密码、可选文件名、预览、重复反馈。
- 用户中心贡献列表和状态时间线。

### QA

- 使用合成 ZIP/7z 样本构建测试夹具，覆盖空密码、Unicode、超长文件名和大文件。
- 验证浏览器计算结果与命令行工具一致。
- 验证并发提交只产生一个候选和多条提交证据。
- 验证日志、错误追踪和 API 响应不泄露密码明文。

### 出口条件

- 注册用户能完成“本地计算→无结果→贡献→个人中心查看 pending”。
- 已验证种子数据能完成“查询→揭示→复制→审计”。
- 1,000 万指纹规模的索引查询压测达到 P95 目标或有优化计划。
- 断网、取消和大文件场景不会卡死浏览器页面。

## 4.4 M3：Windows 桌面验证（第 7–9 周）

### 桌面端

- 创建 WPF 应用、MVVM 分层、依赖注入和日志；启动后检查后端稳定更新通道并提供显式升级下载入口。
- 完成文件选择、流式指纹计算、ZIP/7z 密码测试、超时和取消。
- 首次启动生成安装实例密钥，使用 DPAPI 保护私钥。
- 实现登录、令牌安全保存、安装公钥注册、挑战获取、签名回执提交。
- 明确验证成功标准：至少完成目录读取和受控内容读取，不把“仅打开文件头”视为成功。
- 展示本地隐私提示、网络提交内容和用户确认。

### 后端

- 创建 client_installations、verification_receipts 和 challenge 存储。
- 实现挑战一次性使用、过期、签名校验、时钟偏差和重放拒绝。
- 建立安装实例状态、版本最低要求、撤销和基础风险评分。
- 回执写入证据，但不在此阶段直接实现最终自动晋级。
- 建立桌面版本发布模型、管理员 MFA 发布/撤回流程、流式制品上传与匿名检查/下载接口。

### 管理端

- 接入桌面发布列表、草稿创建、制品上传重试、发布和撤回操作；共享契约与后端字段保持一致。
- 发布前展示通道、架构、版本、最低支持版本、制品大小、SHA-256、合法分发确认和合法性声明，并要求管理员显式确认危险操作。
- 桌面端不要求签名证书；服务端重新计算制品大小与 SHA-256，并以合法分发确认和合法性声明作为发布门禁。

### QA/安全

- 测试签名篡改、旧挑战、重复回执、账号切换、安装撤销和时钟异常。
- 测试恶意/损坏/超大/高压缩比压缩包的资源限制。
- 对桌面端日志、崩溃报告和本地配置进行敏感信息检查。
- 测试版本排序、最低版本、强制升级、错误摘要/大小、未发布/撤回制品、合法分发声明发布门禁和下载完整性。
- 测试管理端发布元数据规范化、最低版本关系、摘要格式、合法分发确认/声明、重试文件名/大小以及原始制品上传请求头。

### 出口条件

- ZIP、7z 代表性样本的成功/失败判断稳定且可取消。
- 伪造 UA、修改回执字段、重放签名均不能获得有效证据。
- 服务端可撤销安装实例，客户端收到明确错误并可重新注册。
- 桌面端不采集主板序列号、MAC 地址或压缩包内容。
- 客户端可从后端稳定通道发现已发布版本并由用户显式打开下载入口；服务端不会向匿名客户端暴露草稿或撤回制品。
- MFA 管理员可在管理端完成“创建草稿 → 上传制品 → 复核 → 发布 → 撤回”闭环，网络中断后可对草稿重试上传。

## 4.5 M4：社区信任、状态机与管理端（第 10–11 周）

### 后端

- 创建 `vote_feedback`、`record_state_events`、`reputation_events`、`reward_adjustment_events`、`trust_cases`、`trust_case_events`、`risk_alerts`、`risk_alert_events` 和 `evidence_correlation_assessments`。举报/申诉统一案件及不可变事件已在 M4 第 2 次迭代完成，`reputation-v1` 不可变信誉事件已在第 3 次迭代完成，状态驱动奖励校正事件已在第 4 次迭代完成，失败激增告警投影与不可变事件已在第 5 次迭代完成，候选关联分析快照已在第 6 次迭代完成。
- 实现规则版本、独立证据判断、状态晋级、隔离、降级和人工覆盖。
- 实现反馈去重、权重、异常关联降权、失败激增告警。M4 第 5 次迭代已完成 15 分钟窗口的独立失败激增检测、聚合告警和管理处置；第 6 次迭代已完成候选内安装/IP 关联图谱、传递闭包分组、结果独立动态限权和不可变聚合快照；第 7 次迭代已完成 `risk-alert-sla-v1`、MFA 值班指派、负责人/超时队列、事务通知 Outbox 和 Worker 有限重试；第 8 次迭代已完成 `notification-webhook-v1`、提供商/回执元数据、投递指标、失败终态和幂等人工重放；第 9 次迭代已完成提供商无关 SMTP、STARTTLS/SSL、认证门禁、纯文本账户/风险模板和 Message-ID 回执。跨候选图谱、真实 SMTP 服务商/发件域名与最终送达验收、排班升级链、指标导出、动态规则和自动处罚待后续完成。
- 完成积分正式结算、回滚补偿和信誉事件。首次验证积分结算、余额投影和 `reputation-v1` 不可变信誉事件已在 M4 第 3 次迭代完成；候选状态撤销/恢复后的 `reward-compensation-v1` 积分补偿和信誉校正已在第 4 次迭代完成。
- 所有自动与人工状态变更写入不可变事件。

### Web/管理端

- 查询结果增加成功/失败反馈、反馈变更和处理结果。
- 用户中心增加反馈、积分、信誉和申诉页面。M4 第 2 次迭代完成举报/申诉，第 3 次迭代完成积分/信誉/反馈历史中心，第 4 次迭代补充奖励失效/恢复事件标签；结果通知和更完整分页交互待补齐。
- 管理端实现候选筛选、证据详情、状态时间线、隔离/恢复/拒绝。M4 第 1 次迭代完成审核垂直切片，第 4 次迭代补充奖励校正时间线和转换汇总，第 6 次迭代补充关联组与动态降权聚合详情；后续补充合并/删除、案件与候选状态编排和危险操作二次确认。
- 实现用户处置、举报处理、系统配置版本、审计查询和基础仪表盘。统一举报/申诉队列、详情、不可变时间线和受控状态处置已在 M4 第 2 次迭代完成；失败激增告警队列、详情和受控处置已在第 5 次迭代完成，第 7 次迭代补齐 SLA 徽标、负责人指派、超时筛选和通知投递历史，第 8 次迭代补齐投递指标卡、失败队列、提供商回执和人工重放入口。

### QA

- 属性/模型测试覆盖状态机不变量：已拒绝候选不可被普通反馈直接恢复，隔离候选不可揭示，积分不可重复结算。
- 并发反馈、并发状态任务和任务重试不产生重复事件；告警 SLA 扫描和通知重试不得重复入队或无限重试。签名 Webhook 必须验证规范载荷、UTC 时间戳和 HMAC；SMTP 必须验证 STARTTLS/SSL、认证、最小披露模板和收件人拒绝；第三次失败必须进入终态，人工重放必须幂等并写审计。
- 管理员越权、CSRF/XSS、对象级越权和批量接口资源消耗测试。举报/申诉首版已覆盖普通用户私有列表、贡献者申诉授权、MFA 管理访问、幂等冲突和审计脱敏。

### 出口条件

- 两个独立有效成功证据能按 `verification-v2` 规则晋级；候选内关联反馈按 `correlation-v1` 动态限权；失败激增能隔离并告警。
- 管理员每次处置都有操作者、受控原因码、可选说明、前后状态和 `request_id`；重复幂等请求不得产生重复状态事件。高风险告警还必须具有可审计 SLA、负责人变化、通知投递状态、提供商/回执元数据和失败重放历史，且管理响应不披露接收地址或签名材料。
- 积分账本余额可由事件重算且与用户显示一致。
- 普通用户无法访问其他用户的贡献详情、举报/申诉案件或管理信息。

## 4.6 M5：稳定、合规与发布（第 12–14 周）

### 第 12 周：系统测试与性能

- 完整 E2E 回归、跨浏览器、Windows 10/11 兼容性测试。
- 容量数据生成、查询/揭示/贡献/反馈混合压测。
- 慢查询、索引、连接池、缓存和 Worker 并发调优；Worker 并发必须显式配置，并按 API、Worker、Scheduler 全部客户端进程核算数据库连接池总预算。
- 在 staging 固化至少 4 小时混合负载、资源采样、单 Worker 故障与 API/MySQL/Redis/Celery 操作阈值；资源趋势报告、MySQL/Redis HA 报告必须通过版本化 schema、profile SHA-256、敏感字段和 checksum 校验，且准入合同、合成夹具与实际运行证据分开记录。
- 完成无障碍检查和主要页面视觉回归。

### 第 13 周：安全与恢复

- 完成 SAST、DAST、依赖与镜像扫描、桌面端静态检查。
- 进行人工安全测试：枚举、越权、重放、刷票、密钥/日志泄露。
- 备份恢复、数据库迁移回滚、密钥轮换、Redis 丢失和 Worker 重启演练。
- 完成隐私政策、条款、授权记录、投诉删除和数据保留配置。

### 第 14 周：RC、灰度与上线

- 冻结 RC，除阻塞缺陷外不再合入新功能。
- 在预生产执行生产同构部署、冒烟、监控与告警演练，并完成 MySQL/Redis 高可用切换的 RTO/RPO 证据；证据包必须标记为 `target-execution`，通过资源趋势/HA 校验后由自动证据门禁输出发布结论。
- 目标执行源必须共享执行组，使用 UTC 时间线，提供资源采样、探针窗口和 HA 生命周期事件；适配器输出需记录源 SHA-256 并排除凭据、连接串、目标端点和逐条业务数据；交接前必须生成封存清单、确定性 ZIP，并绑定候选提交 SHA。
- Prometheus 区间导出必须先规范化为单序列资源指标并完成跨序列时间对齐；托管 MySQL/Redis HA 事件只能保留允许的生命周期字段和原始事件 SHA-256，未经白名单的字段或原始平台标识不得进入证据链。
- 小流量灰度，观察错误率、P95、揭示量、异常反馈和队列积压。
- 达到发布门禁后全量；保留上一版本镜像和数据库回滚方案。

### 出口条件

- P0/P1 为 0，高危安全问题为 0。
- 备份恢复、回滚、密钥轮换和告警通知均有实际演练记录。

## 8. 分支、评审与交付流程

- 主分支始终可发布；功能分支短生命周期，命名 `codex/` 或团队约定前缀。
- 所有变更通过 Pull Request；至少 1 名非作者评审，安全关键代码需 2 人评审。
- 数据库迁移必须包含前滚、兼容窗口和回滚说明；禁止在启动时自动执行破坏性迁移。
- OpenAPI 变更先更新契约，再生成 Web/桌面客户端；破坏性变更需版本升级。
- 每个 PR 至少关联需求/缺陷编号、测试证据、迁移影响和安全影响。
- 每周一次可演示构建；每两周一次范围与风险评审。

## 9. 测试计划

| 测试类型 | 工具/方式 | 门禁 |
|---|---|---|
| 后端单元与集成 | pytest、Testcontainers 或隔离数据库 | 核心模块覆盖率 ≥80% |
| Web 单元 | Vitest | 核心状态与组件通过 |
| Web E2E | Playwright | 核心旅程 100% 通过 |
| 桌面单元/集成 | xUnit 或 NUnit | 指纹、回执、压缩格式核心用例通过 |
| API 契约 | OpenAPI 校验、生成客户端编译 | 无未声明破坏性变更 |
| 性能 | k6/Locust 或等价方案 | 达到 P95 与错误率目标 |
| 安全 | SAST/DAST/依赖扫描/人工测试 | 高危为 0 |
| 恢复 | 备份恢复与故障演练 | RPO/RTO 达标 |

核心端到端用例：

1. 新用户注册、登录、刷新令牌、撤销会话。
2. 浏览器本地计算 SHA-256/MD5，查询无结果并贡献。
3. 桌面端对同一文件本地验证成功，提交签名回执。
4. 第二个独立用户验证成功，候选按规则进入 verified。
5. 注册用户揭示并复制密码，系统正确扣减配额并写审计。
6. 多个独立失败证据触发 quarantined，普通用户不能揭示。
7. 审核员查看证据并恢复或拒绝，审计时间线完整。
8. 并发重复提交、反馈和任务重试不重复建记录或发积分。

## 10. 环境与部署

| 环境 | 用途 | 数据规则 |
|---|---|---|
| local | 单人开发与自动测试 | 合成数据、开发密钥 |
| integration | 合并后集成与契约测试 | 自动重置的合成数据 |
| staging | 预发布、压测、安全和恢复演练 | 生产结构、非生产数据、独立密钥 |
| production | 正式服务 | 最小权限、加密、审计、备份 |

- 镜像必须可追溯到提交 SHA，生产只部署已签名或已批准制品。
- 环境变量只保存非敏感配置；敏感值进入密钥管理系统。
- 部署采用滚动或蓝绿方式；数据库变更遵循先兼容后切换。
- 日志和指标设置容量与保留期限，禁止无限增长。

## 12. 发布与回滚清单

### 发布前

- 配置、迁移、索引、密钥版本和备份检查。
- 合成数据全流程冒烟；生产域名、TLS、CORS、安全头检查。
- 限流、告警、邮件、审计、举报和删除流程验证。
- 桌面安装包签名状态、最低版本策略和下载校验值确认。

### 发布后 24 小时

- 每 30–60 分钟检查错误率、延迟、队列、数据库、揭示量和异常反馈。
- 冻结非必要变更；准备快速关闭密码揭示或贡献的功能开关。
- 若出现数据错误、密钥异常、越权或大规模滥用，立即进入安全事件流程。

### 回滚触发

- P95 连续 15 分钟超过目标 2 倍且无法通过扩容恢复。
- 5xx 超过 2%、核心流程成功率低于 95%。
- 发现越权、明文日志、错误密码大规模揭示或回执验证绕过。
- 数据库迁移导致不可接受的数据错误或无法在时间窗内修复。
