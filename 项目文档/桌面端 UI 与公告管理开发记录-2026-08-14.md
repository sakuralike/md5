# 桌面端 UI 与公告管理开发记录

日期：2026-08-14

## 目标

根据桌面端参考图，将现有 WPF 客户端改造成“用户信息 + 三步验证 + 公告区 + 运行状态”的紧凑工作台，并为后台增加桌面端公告管理。

## 已完成

- 重构 `apps/desktop-windows/MainWindow.xaml`：加入经典分组框布局、账号统计、文件拖放、指纹/验证/提交三步区、公告轮播、更新状态和项目支持说明。
- 保留本地安全边界：ZIP/7z 文件只在本机读取，登录令牌继续由 Windows DPAPI 保护，桌面回执仍通过一次性挑战和签名校验提交。
- 桌面端接入 `GET /api/v1/desktop/announcements`，展示已发布且在有效期内的公告；HTML 公告在客户端降级为纯文本，图片使用首个 HTTPS 图片地址，动作链接通过系统浏览器打开。
- 新增 `desktop_announcements` 数据模型与 Alembic `20260814_0038`，支持草稿、发布、归档、排序、有效期、文本/HTML 内容、图片地址和动作链接。
- Admin 新增“桌面公告”工作区，支持列表、创建、编辑草稿、发布和归档，并加入输入校验与审计。

## 接口与治理

| 用途 | 接口 | 权限 |
| --- | --- | --- |
| 桌面端读取公告 | `GET /api/v1/desktop/announcements?limit=10` | 公开，只返回有效的已发布记录 |
| 管理端列表 | `GET /api/v1/admin/desktop-announcements` | 管理员 + 条件 MFA |
| 创建/编辑 | `POST /api/v1/admin/desktop-announcements`、`PUT /api/v1/admin/desktop-announcements/{id}` | 管理员 + 条件 MFA + 限流 |
| 发布/归档 | `POST /api/v1/admin/desktop-announcements/{id}/publish`、`POST /api/v1/admin/desktop-announcements/{id}/archive` | 管理员 + 条件 MFA + 审计 |

管理员 TOTP 遵循当前规格：默认关闭；仅账号主动启用后才要求动态码。公告内容示例必须使用合成数据，禁止录入真实链接、密码、令牌或密钥。
