# 系统配置与用户审批工作台用户等级职责边界设计

- 日期：2026-08-17
- 状态：已选定，待实现前复核
- 范围：Admin 管理端“系统配置工作台”和“用户审批工作台”的重复“用户等级与权益”入口。

## 1. 背景与目标

当前“系统配置工作台”和“用户审批工作台”均展示“用户等级与权益”。这会让管理员无法判断应从哪个工作台维护等级阈值、每日揭示额度和贡献资格。

目标是使“用户审批工作台”成为唯一可见、可编辑的用户等级与权益入口；系统配置工作台继续负责站点品牌、导航、运行参数和 SMTP 等非用户等级配置。

## 2. 选定方案

采用“仅移除系统配置页面重复 UI”方案：

1. 从系统配置页移除“用户等级与权益”区块、`#user-levels` 锚点和对应二级导航项。
2. 保留用户审批页中的 `UserLevelsManagement`，并保持其加载、校验、直接保存和重置当前编辑能力。
3. 不新增或移除后端 API、数据库表或迁移。现有当前系统配置快照仍携带 `user_levels`，以保持直接保存 API 的完整快照契约和既有调用兼容。
4. 系统配置页面不再向管理员展示或提供修改用户等级的控件；用户等级修改只从用户审批工作台发起。

## 3. 页面职责

| 工作台 | 保留职责 | 移除职责 |
| --- | --- | --- |
| 系统配置工作台 | 站点品牌、Logo、导航、运行配置、SMTP、保存和重置 | 用户等级与权益的展示、编辑、锚点与页内导航 |
| 用户审批工作台 | 用户搜索、审批、角色/状态治理、用户等级与权益的编辑、保存和重置 | 无 |

## 4. 验收标准

- 打开系统配置工作台时，不显示“用户等级与权益”“用户等级规则”或 `#user-levels` 区块。
- 打开用户审批工作台时，仍显示“用户等级与权益”，并保留新增等级、直接保存和重置当前编辑控件。
- 系统配置工作台的其他直接保存功能不回归。
- 相关 Admin 渲染测试、类型检查、Lint 和统一质量门禁通过。
- 实现提交通过 Git SSH 推送，并部署至 Staging；部署后复核 Admin 构建和运行服务健康状态。

## 5. 非目标

- 不变更用户等级规则的业务校验、等级投影重建或服务端权益执行逻辑。
- 不调整当前系统配置的直接保存 API 契约。
- 不引入版本历史、版本差异、发布、回滚或快照机制。
